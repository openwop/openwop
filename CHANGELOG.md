### Pack patches: SSRF + JWT alg-confusion fixes (P0.1) (2026-05-17)

Closes 2 of the 3 High-severity findings from yesterday's pre-audit triage. First step of the `app.openwop.dev` public-deploy hardening (Phase 0). Three packs patched + republished to `packs.openwop.dev`; old versions remain available for pinned consumers.

- **`core.openwop.crypto@1.0.1`** — closes `OPENWOP-AUDIT-2026-001` (JWT alg-confusion / CVE-2015-9235 pattern). New required config fields `expectedAlgorithm` (single) or `allowedAlgorithms` (allow-list) bind the verifier to specific algorithm(s); the token's self-declared `alg` is checked against the caller's allow-list BEFORE any key material is touched. Calls without either field reject with `JWT_VERIFIER_ALGORITHM_REQUIRED` (override for legacy callers: `OPENWOP_JWT_ALLOW_HEADER_ALG=true`, deprecated). JWKS verification gains a `kty`-vs-`alg` cross-check so an `HS256` token can't be verified against an `RSA` JWK by treating the public key bytes as an HMAC secret. Schema: `jwt-verify.config.json` `$id` bumps to `/1.0.1/`.
- **`core.openwop.http@1.1.1`** — closes the http half of `OPENWOP-AUDIT-2026-002` (SSRF). All outbound `fetch()` calls now route through a `safeFetch()` wrapper that: (a) rejects non-http(s) schemes; (b) DNS-resolves the destination hostname and rejects any address in loopback/`127.0.0.0/8`, link-local/`169.254.0.0/16` (covers GCP/AWS metadata), RFC 1918 (`10/8`, `172.16/12`, `192.168/16`), CGNAT (`100.64/10`), multicast (`224/4`), and the IPv6 equivalents (`::1`, `fe80::/10`, `fc00::/7`, `ff00::/8`, with `::ffff:` IPv4-mapped re-checked); (c) strips `authorization`, `cookie`, `proxy-authorization`, `set-cookie` from caller-supplied `inputs.headers`. The retry loop now refuses to retry SSRF-block / scheme-block / DNS-fail errors (they're deterministic). Opt-out for local-dev / self-hosted: `OPENWOP_HTTP_ALLOW_PRIVATE_RANGES=true` on the host process. Production `app.openwop.dev` runs with it unset.
- **`core.openwop.rag@1.0.1`** — closes the rag half of `OPENWOP-AUDIT-2026-002`. `loader-url` and `loader-github` now share an inlined `safeFetch()` (same block-list as the http pack) so they can't be used as SSRF pivots even on hosts that don't restrict pack-level fetch. Also strips `authorization` / `cookie` from caller-supplied `inputs.headers` so a workflow piping LLM output into `headers` can't exfiltrate a verifier bearer.
- **Yank policy.** Old versions (`crypto@1.0.0`, `http@1.0.0`/`1.1.0`, `rag@1.0.0`) stay accessible but will be flagged `deprecated` in the registry index in a follow-up commit (avoid breaking pinned consumers immediately). Yank decision happens after the new versions have soaked on the registry for 7 days. Severity-`high` advisory IDs will be assigned when the external audit confirms gradings.
- **Verification.** All three patched packs verify against `keyId=openwop-team-1` via `registry/scripts/verify-signatures.mjs` (69 / 69 verified). Smoke tests live-confirmed:
  - SSRF: `http://169.254.169.254/`, `http://localhost/`, `http://10.0.0.1/`, `http://[::1]/`, `file:///etc/passwd` all blocked; `https://example.com/` returns 200.
  - Header scrub: caller-supplied `Authorization` + `Cookie` headers stripped before fetch dispatches; an `X-Marker` non-sensitive header passes through.
  - JWT: token forged with `alg: HS256` over the verifier's RSA public key rejects with `JWT_ALG_NOT_ALLOWED` when `expectedAlgorithm: 'RS256'` is configured; legitimate RS256 tokens verify cleanly.
- **`SECURITY/internal-pre-audit-findings.json`** updated: findings 001 + 002 move to `status: "fixed"` with the remediation commit SHA. Finding 003 (agent tool handler) remains open.

### Workflow-chain packs — RFC 0013 Phase 3 (2026-05-17)

- **`conformance/src/lib/workflow-chain-expansion.ts`** (NEW) — reference implementation of the 9-step host-editor expansion semantics from `workflow-chain-packs.md` §"Expansion semantics (normative)". Pure function, zero I/O, zero crypto. Implements steps 3 (typeId resolution check, delegated via `isTypeIdResolvable` callback), 5 (`{{params.<name>}}` literal substitution, recursive into nested config/inputs), 6 (per-expansion chainId-derived node-id rewrite for collision-free splice), 8 (chain-level `capabilities[]` propagation to every expanded node), and edge endpoint rewriting that preserves port-name suffixes and leaves out-of-fragment refs untouched (lets the host wire parent-workflow adjacency post-splice). Exports `expandChain(chain, ctx) → ExpandedFragment` + `ChainUnresolvableTypeIdError`. ~190 LOC. Hosts implementing chain expansion MAY import directly OR port the algorithm; the contract is the spec.
- **`conformance/src/scenarios/workflow-chain-expansion.test.ts`** (NEW) — 13 cases across 5 describe blocks: placeholder substitution (literal + recursive into nested objects + non-placeholder pass-through + same-name multi-position), node id collision avoidance (same chain expanded twice → different ids + chainId-dot → underscore slug + `idMap` surfacing), edge rewriting (fragment-internal refs rewritten + port-name suffix preserved + out-of-fragment refs untouched), capability propagation (copied uniformly + omitted when chain declares none), and runtime-invariance contract (expanded fragment carries ONLY concrete typeIds, no chain reference survives).
- **`conformance/src/scenarios/workflow-chain-unresolvable-typeid.test.ts`** (NEW) — 5 cases: rejection throws `ChainUnresolvableTypeIdError`; error carries `code` + `typeId` + `chainId` for actionable diagnostic; rejection happens BEFORE any output is produced (no partial expansion); positive sanity (expansion proceeds when every typeId resolves); fail-fast on the FIRST unknown typeId in declaration order.
- **`conformance/src/scenarios/workflow-chain-pack-signature-verification.test.ts`** (NEW) — 4 cases: valid manifest + signature MUST verify (Ed25519 over `pack.json` bytes per `node-packs.md §Signing`, reused unchanged); tampered manifest MUST fail verification (byte-level tamper detection); wrong-key signature MUST fail; chain-pack manifests carry the SAME `signing` block shape as node packs (`publicKeyRef` / `signatureRef` / `method`). Proves the spec's design intent that workflow-chain packs reuse 100% of the node-pack signing infrastructure.
- **All 3 scenarios are server-free**, run in <1s combined (22 assertions across 209ms), and pass unconditionally — they validate the spec corpus itself. Host-side end-to-end expansion scenarios will continue to gate on `capabilities.workflowChainPacks.supported: true` when a reference host implements the editor flow.
- **`conformance/README.md`** narrative updated to mention the three new scenarios chronologically; scenario count was already at 141 (correct after this batch's additions).

This commit closes RFC 0013 acceptance criterion #5 ("workflow-chain-expansion.test.ts: parameter substitution + id collision") and the deferred Phase 2/3 conformance scenarios from Phase 1's CHANGELOG note.

### Workflow-chain packs — RFC 0013 Phase 1 (2026-05-17)

- **New `kind: "workflow-chain"` pack format** alongside the existing node packs. Pre-configured DAG fragments published as registry artifacts; host workflow editors expand them inline at workflow-author time, substituting `{{params.<name>}}` placeholders and rewriting node ids for collision avoidance. The runtime dispatching engine sees only the expanded concrete `core.*`/published-vendor typeIds — no new dispatch surface required, preserving the "every dispatched typeId has a runtime executor" invariant.
- **New spec doc** `spec/v1/workflow-chain-packs.md` (`Draft`) — normative manifest format + WorkflowDefinitionFragment shape + expansion semantics + error codes (`pack_kind_invalid`, `chain_unresolvable_typeid`, `chain_parameter_invalid`, `pack_signature_invalid`).
- **New schema** `schemas/workflow-chain-pack-manifest.schema.json` (JSON Schema 2020-12, `$id` under openwop.dev, `additionalProperties: false` on every object) — disjoint peer to `node-pack-manifest.schema.json` via the `kind` discriminator (`const: "workflow-chain"` here vs `const: "node"` on the node-pack schema).
- **Optional `kind` field** added to `schemas/node-pack-manifest.schema.json` — `const: "node"` so the existing schema accepts manifests with `kind: "node"` or no `kind` field (backward-compat: every existing manifest preserves its semantics). Manifests carrying `kind: "workflow-chain"` validate against the new peer schema instead.
- **New capability** `Capabilities.workflowChainPacks: { supported: boolean }` — hosts that implement chain expansion advertise `true`; conformance scenarios gate on the flag and skip cleanly against hosts that omit it.
- **New conformance scenario** `conformance/src/scenarios/workflow-chain-pack-manifest-validation.test.ts` — server-free, runs in <1s, exercises positive sample + two negatives (kind/contents mismatch via `additionalProperties` violation; invalid `chainId` via `pattern` violation) + a defensive case for missing `kind` field.
- **Cross-reference added** to `spec/v1/node-packs.md` §"Manifest format" pointing at the new workflow-chain spec doc.
- **README + schemas/README + conformance/README** updated to surface the new doc, schema, and scenario.
- **Wire-shape impact:** all changes additive per `COMPATIBILITY.md` §2.1. No existing manifest is invalidated. No existing workflow JSON shape changes (the expanded result uses the existing `WorkflowDefinition` schema). No existing dispatch surface changes.

- Phase 4 — Conversation as run primitive: `conversation.start` / `conversation.exchange` / `conversation.close` suspend variants.
- Phase 5 — Orchestrator-supervisor: `core.orchestrator.supervisor` typeId + `OrchestratorDecision` schema + `runOrchestrator.decided` event.
- Phase 6 — `core.dispatch` core node: conservative dynamic graph mutation (CP-2); causationId propagation per RFC 0007 §E.
- WASM ABI — RFC 0008 Active; reference Rust pack at `examples/packs/rust-hello/` (28 KiB wasm32); Wasmtime-free loader at `examples/hosts/in-memory/src/wasm-loader.ts`; six conformance scenarios; deliberately-misbehaving packs for memory-cap (`examples/packs/rust-misbehaving-memory/`) and ABI-mismatch (`examples/packs/rust-misbehaving-abi/`) positive-path testing. Schema extension: `capBreached.kind` enum gained `wasm-memory`, `wasm-fuel`, `wasm-execution-time` (RFC 0008 §K). New optional capability `capabilities.nodePackRuntimes.wasm.loadedPacks[]` surfaces accepted pack names; rejected packs (declared ABI not in `abiVersions[]`) MUST be absent — drives the conformance positive path since rejection happens at load time before any node-invoke surface.
- OTLP/gRPC collector (Track 11 closure) — `conformance/src/lib/grpc-framing.ts` (hand-rolled length-prefixed gRPC HTTP/2 framing, zero npm deps) + `OtelCollector.startGrpc()` (parallel `node:http2` server, shared spans/metrics store). New optional capability `capabilities.observability.otel.exportProtocols[]` advertises the supported OTLP transports (`http/json`, `http/protobuf`, `grpc`); `spec/v1/observability.md` gains a §"Export protocols" normative section. New conformance scenario `otel-emission-grpc.test.ts` gates on the array. Opt-in via `OPENWOP_OTEL_COLLECTOR_GRPC=true` (default port 4317).
