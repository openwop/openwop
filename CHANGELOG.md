# OpenWOP Spec v1 — Changelog

All notable changes to the openwop v1 spec, schemas, OpenAPI/AsyncAPI, conformance suite, and reference SDKs.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1/) loosely. Versions are spec-corpus-wide (one date, multiple artifact updates per row); per-artifact versions live in their respective `package.json` / schema `$id` fields.

> **Status legend** (per [`/governance/spec-status/`](https://openwop.dev/governance/spec-status/)):
> Stable · Stabilizing · Draft · Experimental — see individual doc headers for current state. The legacy `STUB / DRAFT / OUTLINE / FINAL` vocabulary still appears in older releases below; both are valid in the corpus.

> **Package version map.** The version headers below are **spec-corpus** versions, not package versions — each package advances independently on its own per-package release tag. So a corpus version may be skipped here when its number was already consumed by a single-package release, and not every published package version has a corpus row. Notably **there is no corpus `1.1.6`**: that number was taken by a TypeScript-SDK-only npm patch (`@openwop/openwop@1.1.6`, published 2026-05-31, the agent-platform/roster helper catch-up), so the corpus skipped straight to `1.1.7`. A deep-link like `#v1-1-6` therefore has no anchor here by design — the TS SDK's own history lives in [`sdk/typescript/CHANGELOG.md`](https://github.com/openwop/openwop/blob/main/sdk/typescript/CHANGELOG.md) and on npm. Current published per-package versions (as of the `1.1.7` corpus release): `@openwop/openwop` **1.2.0** (npm) · `@openwop/openwop-conformance` **1.18.1** (npm) · `openwop-client` **1.1.7** (PyPI) · `github.com/openwop/openwop/sdk/go` **v1.1.7** (Go modules).

## [Unreleased]

- **First row of RFC 0162's conformance table lands: `durability/poison-exhaustion` (suite `1.138.0`, +1 scenario → 465).** §C.8 has two clauses and the easy one was already covered — `failure-path.test.ts` asserts that the `conformance-failure` fixture reaches terminal `failed`. **That says nothing about the second clause.** A host that redelivers forever also reports a terminal status eventually, or reports one while the work keeps being re-dispatched behind it, and an assertion that stops at the status cannot tell *"terminated after N attempts"* from *"still going"*. So the load-bearing leg is **stability after terminal**: count attempts on the run's own log, wait a scaled quiet window, count again, assert unchanged. A host still redelivering records more. **`node.started` and `node.retried` are both counted**, so a host that re-dispatches without emitting `node.retried` is still caught.
- **What it deliberately does not assert, and why.** Conformance to a *specific* declared attempt bound. RFC 0162 §E mints no advertised field, so the bound is not on the wire; asserting against a number the suite invented would be a bound of the suite's own making — the inverse of §B.5's *"derived from the mechanism that enforces it"*. The ceiling leg runs only when an operator supplies `OPENWOP_DECLARED_ATTEMPT_BOUND`, the same operator-supplied-input shape as `OPENWOP_OPTED_OUT_PROFILES`. Boundedness is asserted either way; only the specific bound needs the input.
- **A fifth comment-versus-code-shaped defect, caught in this scenario's own first CI run.** The `inapplicable` disposition was recorded inside the `it` body — but `describe.skipIf` never runs the callback, so that line was **dead code on exactly the path it existed to classify**, and the row would have recorded `blocked` with the unclassified-return marker instead. Same shape as the note written after `ctx.skip()` threw. Found by reading the CI log rather than by any failure: this file and `failure-path.test.ts` both skipped against the postgres host, which does not advertise the `conformance-failure` fixture — **so the reference host in CI cannot witness §C.8 either**, and the disposition is now recorded at module scope.
- **Honest about its gating, after two corrections in the other direction.** This is **not** a pure black-box scenario: attempt counts live on the run's event log, read through the **existing** `/v1/host/sample/test/runs/{runId}/events` seam — no new seam, but a seam, and a host that has not wired it records `blocked` (*unobservable, not unmet*). Outside every profile floor. Of RFC 0162's six conformance rows this is the only one causable without a process termination: `duplicate-delivery` reads as black-box but is not, because §C.7 is about post-acceptance **redelivery** the suite cannot cause — a same-`Idempotency-Key` retry witnesses Layer-1 client dedup, a different mechanism wearing the same name.

- **The largest unmeasured MUST NOT on the replay surface is now witnessed on the wire, and shown to be falsifiable (suite `1.137.0`, +1 scenario → 464).** `replay.md` §"Host-initiated fan-out is an external effect" had **no conformance scenario and no SECURITY invariant**: two hosts had it deployed and `INTEROP-MATRIX.md` still had to record it as *not suite-witnessed*, because a host's own test is evidence about that host, not a witness of the wire. `replay-fanout-suppression.test.ts` makes the suite **be the subscriber** — three legs in ONE `it` against ONE receiver and ONE subscription: a positive control, the MUST NOT after a `mode: "replay"` fork, and a `branch` boundary leg. Run in **three** configurations on a live tier-1 host: `blocked` in 41 ms on a default config (SSRF guard refuses the loopback receiver — correct), **pass** in 7.6 s with the opt-in, and **red** with the host's suppression deleted. **The third is what makes the first two mean anything** — a negative assertion never shown to fail is not evidence. Two reusable techniques came out of it: **wall-clock refutes disposition** (the scenario cannot honestly pass under ~7.5 s, so a 41 ms green was arithmetically impossible — where a scenario has a floor on its own runtime, duration is a free vacuity check needing no instrumentation), and the requirement **records its own disposition at every exit** so a file-level pass earned by the control cannot certify a MUST NOT that never ran (gap G8).
- **NEW `SECURITY/threat-model-replay.md`, and the harm is deliberately not filed as leakage.** Every other model here is mostly about things escaping; **nothing escapes in this one.** A replay re-emits true records, to an entitled subscriber, over a correctly signed channel — every check passes. The falsehood is carried by the *act of delivering*: **a true-shaped false statement**, which a subscriber cannot detect by validating anything. Worse, **a correct re-emission defeats subscriber dedup by construction**, since the re-emitted envelope legitimately carries a fresh `eventId` and webhook dedup keys on `(subscriptionId, eventId)`. Filing this under `threat-model-secret-leakage.md` would have stretched that document *and* added an 80th untraced pointer to the 79 counted a day earlier. NEW protocol-tier invariant **`replay-fanout-no-refire`** (184 rows, 153 protocol-tier).
- **`blocked` here means *unobservable*, not *unmet* — stated in the threat model, not in a footnote.** The scenario needs a host to accept a loopback receiver; a host with an SSRF guard correctly refuses one, and one certifying host additionally requires `https:`, a spec MUST no bypass should touch. That host **declined the opt-in on the ground that it would not have produced the witness it was being traded for** — two independent rejection grounds returning the same code — which is a stronger reason than reluctance. So the scenario sits **outside every profile floor**: a floor must not punish a host for a security control. The tier-1 witness's dependence on an operator opt-in is disclosed as **a property of the evidence**. A host's offer of a durable `suppressed_replay` record to assert on instead was **declined**: asserting on it would mandate host behaviour the spec never asked for, invented by the test rather than the rule.

- **The suite's reference webhook verifier rejected the exact signature header the spec mandates (suite `1.136.15`).** `webhooks.md` §"Delivery headers" specifies `X-openwop-Signature: sha256={hex}`, and its verification recipe says to strip the `sha256=` prefix. `lib/webhook-receiver.ts` required **`v1=`** and returned `malformed_signature_header` for anything else — so the verifier a subscriber implementer copies refused every conforming delivery. The conflation is visible one comment above the check: `v1` is the value of the *algorithm* header (`X-openwop-Signature-Algorithm`), a different field. **One value, two fields.** It survived because `webhook-receiver-adversarial.test.ts` signs with `signPayload` and verifies with this function — **a closed loop that is self-consistent and wrong, and therefore green on every host.** The new `webhook-receiver.test.ts` pins the header against a hand-built spec-shaped value rather than against the suite's own output, which is the only version of that test that could have caught this.
- **`webhook-signed-delivery.test.ts` required a field the contract does not define.** It read `subscriptionId` from the 201 body while `api/openapi.yaml` declares `required: [webhookId]` with no `subscriptionId` property, `webhooks.md` §"Register" shows `{"webhookId": …}`, and the sibling `webhook-tenant-isolation.test.ts` reads `webhookId`. **A spec-conforming host failed at the first assertion** — the suite being *different* from the spec, which is worse than the stricter-than-spec case `COMPATIBILITY.md` §2.3 forbids. Nothing went red because the postgres reference host returns both names, one of them labelled a historical alias in its own source. Both defects reported by a tier-2 host that emits exactly what the spec shows and could not adjudicate which of the suite's three signature shapes was canonical.
- **A fourth comment-versus-code instance, in the file documenting a security contract.** `webhook-signed-delivery.test.ts`'s docblock claimed the scenario verifies `X-openwop-Subscription-Id`; the assertion had checked `X-openwop-Webhook-Id` since a 2026-08-09 correction that never reached the header comment. Also fixed: the tamper case's hard-coded `flipIndex = 5`, which sat inside the hex only while the prefix was the three-character `v1=` and silently moved *into* the prefix when it was corrected — turning a tampered-HMAC case into a malformed-header one. It is now derived from `SIGNATURE_PREFIX`. **The test caught that one; the constant is what makes it stay caught.**

- **"A scenario that recorded its own file id first wins" was true of half the cases (suite `1.136.14`).** `setup.ts` has carried that comment on its automatic file-level record for as long as the record has existed. `recordRequirement` throws on a **conflicting** disposition, so the explicit record did win on disagreement — but when the two **agree**, the automatic call reached `ledger.set` and silently replaced the scenario's own `detail` and `assertionCount` with the file-level ones. Harmless while a passing row rarely carried a detail; **live the moment the `partial-witness:` marker shipped one release earlier**, since a scenario that explicitly recorded `executed-pass` for a requirement it really did exercise — in a file whose *last* leg soft-skipped — would have been stamped "may not have witnessed this" over its own finding, injecting false positives into exactly the measurement that marker exists to produce. Found by a host asking which record lands before building on the answer. `setup.ts` now guards on a new `hasRequirement()`, and the precedence is pinned in `requirement-ledger.test.ts` in both directions. **The comment is true of both cases now.**

- **A ledger note was being discarded exactly where a scenario is best written (gap G8, suite `1.136.13`).** `resolveFileRecord` honours a file's soft-skip note in two branches: zero assertions, or every test `ctx.skip()`ped. **`return softSkip(...)` produces a *pass* state, not a skip** — so a file that asserts anything first (a positive control, a setup precondition) and then soft-skips hit neither branch, the note was dropped, and the row read a bare `executed-pass` for a requirement the run may never have reached. Measured on the function directly by a tier-1 host, no host involved: `['pass'], assertionCount 1, noted blocked` → `executed-pass`, reason gone. **This is the same defect as the note-after-`ctx.skip()` case that function's own comment already records** — that one was fixed, note-after-*assertion* was not, and both hid because nothing goes red. The perverse property: **the better the scenario, the more convincingly it mis-certifies**, because a positive control is what supplies the assertion that suppresses the note. Interim fix retains the note as a `partial-witness:` detail and **deliberately does not move the disposition** — honouring a per-*file* note would downgrade a file that legitimately finished its requirement *and* soft-skipped an optional extra leg, trading a false positive for a false negative. Affected rows are now self-identifying in every bundle, turning a static count of 75 `softSkip` positions across 36 files into a measured count of real occurrences; the durable per-`it` fix should follow that evidence. Recorded as gap **G8** in `conformance-certification.md`, pinned in `conformance-execution-witness.test.ts`, sabotage-checked both directions.
- **`check-security-invariants.sh` never checked the `threat_model:` pointer, and 79 of 183 invariants point at a document that never names them.** The gate verified that a protocol-tier invariant's test glob resolves; the threat-model field was parsed and then ignored — so an invariant could cite a threat model that says nothing about it and stay green. **A pointer nobody verifies is an unchecked claim**, the same shape as the drift guard that masked a suite and the poll knob that reached no call site. Reported by a host that declined to file an invariant whose pointer it would have had to make true by asserting it. A **missing** pointer file is now a hard failure; a file that exists but never names the invariant is a **ratchet** at the measured baseline of 79 — it may not grow, and the gate tells you to lower it when you trace one. A cliff would have red-lit every contributor or invited 79 rubber-stamp edits, and the rubber stamp is the thing being fixed.
- **`replay.md` §"Host-initiated fan-out": the lifecycle-vs-recorded-fact contrast ranks the harm, it does not narrow the scope.** Clarified after a host implementing the section read it as a possible carve-out. The requirement below it already decides the question — replay-ness is read from the run, never from the event type — so a host suppressing only recorded-fact deliveries is selecting by event type and is non-conforming, notwithstanding that the harm it leaves is the milder one. Editorial: no conformance-affecting change, an invitation to misread removed.

- **The documented way to widen a poll bound never reached the scenarios that needed it (suite `1.136.12`).** `polling.ts` advertised `OPENWOP_LIFECYCLE_TIMEOUT_MS` as the knob for long polls, but it supplies the **default** only — and ~110 call sites pass an explicit `timeoutMs`, 59 of them passing the same `10_000` the default already was. An operator measuring a host on a cold or contended endpoint would set the documented variable, see no change, and record an `executed-fail` that measured the **environment, not the host** — a bundle attributing to the wrong subject, the same family as gap G3. **`OPENWOP_POLL_TIMEOUT_SCALE`** (default `1`) multiplies *every* bound, explicit or default. It scales rather than floors deliberately: a floor would flatten the deliberately-short bounds some negative assertions depend on, while a scale preserves each call site's intent relative to the others. At the default it is an exact no-op, so no existing measurement moves, and a mis-set value (`0`, negative, unparseable) falls back to `1` rather than turning every poll into an instant failure that reads as a host defect. **Neither knob can make a hanging host pass** — the assertion is that a terminal state is *reached*. Asserted in `src/lib/polling.test.ts` and sabotage-checked (a no-op implementation and a floor implementation each fail 4 of the 7), because shipping an untested knob to replace a knob that didn't work would repeat the defect one layer up.

- **The G3 build-reproducibility recommendation has its first adopter, and the path there is worth more than the outcome.** MyndHyve bundle v2 **#15** (suite `1.136.11`, `workflow-runtime-00572-noc`) is the first bundle in the programme measured against a **reproducibly built image** — the host that discovered G3 by rebuilding one commit into 283/22 vs 303/2 has made its builds lockfile-respecting. `conformance-certification.md` §G3 now records that switching to `npm ci` **failed the build loudly** (five packages missing from the lock) and that `--omit=optional` could never have helped, because the installer validates lock/manifest sync *before* honoring omit filters; what worked was pinning the installer to the version that **wrote** the lock. **The seam is writer/reader agreement, not the lockfile alone.** The host's residual — a lock still missing entries, pinned around rather than regenerated, and a guard that can assert a pin exists but not that it is the right one — is recorded too: this is a build that is now *re-checkable*, not one that is proven closed.
- **`INTEROP-MATRIX.md`: MyndHyve bundle v2 #15 recorded, and the numbers were re-derived from the artifact rather than transcribed.** 304 executed-pass / 1 executed-fail / 0 skipped / 75 inapplicable / 89 blocked over a 469-row ledger, all 14 profile lines certifiable, **zero zero-assertion passes**, all 36 floor rows in a certifiable disposition. The single failure (`run-transport-economy`, a wall-clock latency leg) is published as **`executed-fail` rather than re-run until green**, and of four runs only the last is evidence — with both discarded modes named, including an expired API key that would have read as a catastrophic regression *caused by the build change shipped minutes earlier*.
- **Stated where the corpus measures nothing: the new host-initiated fan-out rule has no conformance scenario.** Both hosts that implement `replay.md` §"Host-initiated fan-out is an external effect" now have it **deployed** — the second (`#224`) on the revision bundle #15 was measured against — but the suite contains no leg for it, so neither row is suite-witnessed and both rest on the hosts' own tests. The matrix says so in the row rather than letting "DEPLOYED-WIRE" imply otherwise: a normative MUST NOT with no scenario is measured by nothing.

## [1.8.0] — 2026-08-18 — the evidence-integrity cycle: what an artifact actually measured

No new RFCs and no `Active → Accepted` promotions (**Accepted 153, Active 3 — 0035 / 0111 / 0121 held —, Draft 1 — 0038 Parked**). This cycle repaired the *evidence* layer instead: a recurring defect in which a gate, a test, a spec sentence, a build, or a bundle **reported, but not on what its reader assumed it measured**. Five instances were found and closed, four of them by a host checking its own tree and disclosing the result. All wire shapes additive per `COMPATIBILITY.md` §2.1; one erratum classified safety-fix and one correction recorded as W3C-Class-3 conformance-affecting.

- **RFC 0151 compensation is finished as prose and witnessed on a deployed origin.** §C lifecycle / §E operator recovery / §G threat model landed; **UQ4** decided (`irreversibleEffect`, the author's statement that an effect has no inverse, mutually exclusive with `compensation` by schema); **UQ5** resolved as a **minimum, never a window** — a host measured that its obligations have no retention purger at all, so a ceiling would be uncompliable without building one and would fight RFC 0053 dead-letter handling; **G4** closed (a fork folds over its own inherited log; a non-terminal inherited plan is *not* inherited as an obligation — a fork is not a transfer of custody); and §F's *"explicit authorization"* clarified as an RFC 0049 decision bound to tenant/principal/action/`planVersion`, **not** the authored trigger policy. `waiveRequiresApproval` added (§B) with escalation as a floor a node-level `false` cannot lower.
- **A host MUST now refuse, at registration, a policy naming a trigger it does not fire** (`validation_error`) — classified **safety-fix**, because silently accepting a guarantee that never fires surfaces only during the incident the policy existed for. Deliberately **no advertisement surface**: `supportedTriggers` stays frozen under RFC 0147 §A.1, and the freeze analysis is now recorded *at the refusal itself*, because relaxing the refusal would invert it.
- **The replay/re-emission contract was never ambiguous — the test was.** `replay.md` caveat 5 has required recorded-fact re-emission since v1.2; RFC 0057 §D carried an implementation note that read as permission to suppress and conceded it met only half the rule. Note retired (recorded as **W3C Class 3** — conformance-affecting, not editorial: a suppressing host is now clearly non-conforming where its status was arguable). The leg asserted inside a `for` loop over the replayed events, so a host emitting **none** passed vacuously — **two hosts with opposite behaviour both stayed green for months.** Both halves are asserted now.
- **NEW normative rule: host-initiated fan-out is an external effect.** Every prior statement of "replay MUST NOT re-fire external effects" was scoped to *nodes*, leaving event-log fan-out unspecified — so a `replay` fork delivered webhooks asserting work it never performed, and a *correct* re-emission defeats subscriber dedup by construction (fresh envelope `eventId`). `replay.md` §"Host-initiated fan-out": suppress outbound delivery for re-emitted events, read replay-ness **from the run** not the event type, `branch` out of scope, unconditional. Found independently by two hosts — in the second as a *written, reasoned exemption* the rule negates — and **deployed-wire the same day**.
- **A certification bundle attributes to a BUILD, not a commit.** `conformance-certification.md` claimed v1 bundles were "reproducible … against the same host commit"; a host rebuilt one commit and scored **283/22 against 303/2** (its image ran `npm install`, not `npm ci`). Claim retired; new gap **G3**: a bundle is evidence about *one execution of one build*, a verifier MUST re-run the same **build** or say which, and `host.build` / `host.commit` are now documented in `certification-bundle-v2.schema.json` — with the identifiers ranked by *when each is available*, since an image digest does not exist for a bundle baked into the image.
- **RFC 0150 §A lands in `idempotency.md` (v1.5), and the mismatch error finally has a canonical name.** Record shape (`requestDigest`, `pending|completed|retryable-failure|terminal-failure`, lease owner/expiry), tenant from authenticated context **never the body**, atomic CAS reclaim, and the `MUST NOT` on host-generated identifiers sharing the caller keyspace. **`idempotency_key_mismatch` is canonical**; `idempotency_key_conflict` retired. Four artifacts had disagreed because the spec named no error and the leg asserted the `409` status but never a code.
- **`storage-adapters.md` gains §"Claim acquisition"** — cited by four artifacts since RFC 0009, including a normative MUST, and never written. Atomic compare-and-set acquisition, holder-scoped heartbeat shorter than the TTL, **expiry as the only reclaim authority**, resume-on-startup, and the event-log invariants under claim transfer (a transfer is *not* a run event, because replay must not depend on which process executed).
- **Gates that reported without measuring.** The RFC 0013 drift guard was step 4 of the soak job, so its failure **masked the strict conformance suite and the multi-process durability scenarios for two months**; it now runs in its own job, and a second mirrored region (RFC 0157 compensation) is compared. `PROTOCOL-STATUS.md`'s reference-host table matched an unpadded header and had silently been empty. A profile floor can no longer cite a scenario that does not exist — or one that is corpus-only and therefore **`blocked` in the published package forever**.
- **Twenty-five suite defects (S22–S46), every one measured by a host rather than found by review.** Highlights: the error-envelope schism decided **flat** (`details.retriable`); 44+14 readers that consulted only the deprecated `capabilities` wrapper; `capabilities.mcp.serverUrls` required by a scenario and forbidden by the schema; `discoverOwnedTenant()` reading a field no schema-valid host emits; the `tarball_too_large` probe that uploaded 60 MB into a proxy's 32 MiB ceiling instead of inflating a 64 KB gzip; and eight files whose `softSkip` sat *after* `ctx.skip()` and so never recorded a reason.
- **RFC 0147 program items closed:** RFC 0155 §C extension registry **81 uncovered → 0**; RFC 0156 §F assurance manifest + claims gate and §G single-source security SLA; RFC 0154 §E provenance verified from a clean checkout and §B negative chain legs; RFC 0149 UQ3 measured against a live sibling host. Hand-typed tallies are now gated against the tree.
- **Host evidence, stated at the strength it holds.** openwop-app reached deploy #7 with RFC 0151 and RFC 0153 §B/§D/§E deployed-wire and `openwop-memory` certified; MyndHyve reached bundle #14 with `executed-fail 0` and 13 profiles certifiable. Values withheld with reasons are recorded as such — `replay.sideEffectSuppression` stays `none` because "do not perform" and "resolve the recorded outcome" are different obligations, and a `suiteVersion` pin is recorded as **measured, never rounded up**.
- **Conformance suite `1.123.0 → 1.136.11`** (published), **+6 scenario files → 463**, invariants **181 → 183**. No net-new scenarios since the last suite tag, so this corpus tag re-publishes nothing.
- **Known red, stated rather than discovered:** the `Conformance Soak` workflow's SQLite host lane is failing. That lane was **invisible for two months** behind the drift guard and is red because the strict suite now actually runs; the backlog is triaged but not cleared, and it is deliberately **not** silenced with profile opt-outs. The drift-guard and registry jobs are green.

## [1.7.0] — 2026-08-16 — the integrity-program cycle: non-vacuous certification, versioned A2A/MCP composition, and the first host witnesses (RFC 0146–0157)

Lands the RFC 0147 protocol-integrity program end to end: RFCs 0146–0157 reach `Accepted` (**Accepted 141 → 153**, Active 3 — 0035 / 0111 / 0121 held —, Draft 1 — 0038 Parked), certification stops being able to lie by omission, A2A 1.0 and MCP 2026-07-28 get profiles + suite peers + real host witnesses, and every carried item is written into its RFC rather than implied. Suite `1.72.2 → 1.123.0` (412 → 457 scenario files; 34 net-new), invariants 160 → 175, prose docs 52 → 60, schemas 63 → 80. All wire shapes additive per `COMPATIBILITY.md` §2.1 except the three recorded safety-fixes (RFC 0148 evidence, RFC 0149 §A/§C, RFC 0150 §B), none of which moves a shape a conforming host emitted.

- **RFC 0147 program `Draft → Accepted` (0147–0156) + RFC 0157 errata + RFC 0146 provenance.** Nine child RFCs each carry their own acceptance gates; seven of thirteen program annotations that said "carried" about landed work were corrected; criteria 2, 11, 12 checked; all twenty gap/risk registers dispositioned (131 rows). Externally gated criteria (audit, second maintainer, Tier-3 host, independent assessment) remain open by their own text. RFC 0146 `contractProvenance` `Active → Accepted` with both halves witnessed on one wire.
- **Certification can no longer read silence as a pass (RFC 0148).** Requirement ledger (`executed-pass|executed-fail|skipped|inapplicable|blocked` per requirement, `assertionCount` witnesses), certification bundle **v2** with a required `blocked` total, `--certify` exits 3 on an unclassified return, consumer verifier `verifyBundleV2`, evidence scrubbing (SR-1 canary), a floor for **every** catalog profile (discovery-conditional for `openwop-replay-fork`, runtime-derived for `openwop-node-packs`), and every named scenario on disk (`conformance-execution-witness`, `conformance-advertised-seam-required`, `certification-bundle-non-vacuous`, `certification-bundle-redaction`). Bundle v1 sunsets for new claims 2026-11-10 (`version-negotiation.md` runbook). The historic in-memory bundle was invalidated and **all four reference hosts reissued as v2** (`openwop-examples#14`).
- **The core-standard floor named a file that never existed.** `audit-log-verification.test.ts` had sat in `PROFILE_FLOOR_SCENARIOS` since RFC 0088; the ledger surfaced it on its first end-to-end run. Removed by the floor's own no-soft-skip rule (eight-file floor); `core-standard-manifest.json` regenerated.
- **Scenarios say why they return early.** 84 silent-return files → `softSkip(kind, reason)` / `seamAbsent` (blocked by default, FAIL under `OPENWOP_REQUIRE_BEHAVIOR=true`; a 403 is no longer a pass); a zero-assertion file with no reason is `blocked`, never a pass; `behaviorGate` records `inapplicable`/`skipped` into the ledger; the advertise-vs-opt-out `MUST NOT` throws instead of warning.
- **Machine contracts reconciled (RFC 0149).** `servers[].url` no longer doubles `/v1` (44 operations resolved `/v1/v1/*`); `protocolVersion` grammar `MAJOR.MINOR` enforced in schema + predicate + prose; discovery examples unwrapped to root layout; `discovery-canonical-family-no-shadow`; lifecycle-coherence gate for RFCs ≥ 0147; **normative examples extracted and validated** (`<!-- normative-example: … -->`, 26 declared); `spec/v1/operation-path-manifest.json` + `openapi-asyncapi-sdk-parity` hold OpenAPI, AsyncAPI and the SDK path table to one resolution.
- **Effect identity, replay digest, split-brain (RFC 0150).** Layer-2 identity retired the `attempt` component (safety-fix; zero deployed keys per the v1 inventory); semantic-request digest v2 (JCS) with golden vectors; `crossRegion: fenced-effects` and stale-owner vocabulary; three new invariants. Fenced-effect and pending-lease witnesses still wait for a fencing host.
- **Compensation profile (RFC 0151 + 0157).** `capabilities.compensation`, node/settings policy (`compensation-policy.schema.json`), six content-free `compensation.*` events, `compensationStatus` on `RunSnapshot`, `spec/v1/compensation.md`, `compensation-replay-no-refire`, and the behavioural witness + §21 seams — `blocked` until a host advertises the family (openwop-app ADR 0554 P2 merged; advert pending).
