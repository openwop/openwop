# RFC 0140 — Gap register

| ID | Section | Question / Missing Input | Owner | Resolution Path | Blocks |
|---|---|---|---|---|---|
| G1 | §B.4(b) | **No host implements the default-deny effect-seam guard.** The reference host has §B.1/§B.2 (classifier + `replay_source_missing`) via ADR 0326 P3b + ADR 0341, but no run-scoped ambient context and no seam guard — so no host can honestly advertise `recorded-outcome` at the moment §B is written. | Steward | Build the guard in openwop-app before the `Active → Accepted` witness. Until then §B.4 is normative text with no implementation behind it. | The `Accepted` flip — this is the acceptance witness |
| G2 | §Conformance | **The counter is host-attested.** A host-sample seam means the host counts its own effects; a host whose guard leaks would also have to mis-count to stay green. A suite-side sink would be stronger evidence but needs a URL-injection mechanism for seeded fixtures that the suite does not have. | Conformance Architect | Documented as a limit in `coverage.md` rather than papered over. Revisit if fixture input-injection ever lands. | Nothing; bounds what a green run may be said to prove |
| G3 | §A | **Declaring the `replay` block retroactively schema-validates existing readers.** Six conformance scenarios and two profile predicates (`profiles.md` §`openwop-replay-fork`, `agent-platform-profile.md`) currently read an unvalidated object. Declaring it means a host emitting a `modes` value outside `["replay","branch"]` now fails schema validation where it previously passed. | Schema Architect | The block is declared **open** and every field optional, so only the `modes` item enum is newly constraining. Survey `INTEROP-MATRIX.md` advertisements at `Active → Accepted`; drop the item enum to a bare string if any host is affected. | Nothing today; may force a schema loosening |
| G4 | §D | **`branch` remains unsuppressed and unwitnessed.** The asymmetry is deliberate, but no scenario asserts it, so "branch re-fires" is documented behavior with no test. A host could suppress branch effects too and no one would notice. | Spec Architect | The §D caution makes it explicit for operators. A scenario would need a second fixture and would assert a *permission*, not a requirement — deliberately not built. | Nothing |
| G5 | §Motivation | **How many hosts actually violate caveat 1 is unmeasured.** The claim "an implementer who follows the spec literally re-fires effects" is argued from the mechanism, not surveyed. Only openwop-app's behavior is known. | Compatibility Architect | Survey advertisements at `Active → Accepted`. The argument holds regardless — the mechanism is provably inoperative — but the count affects how loudly the correction is announced. | Nothing; affects release notes |
| G6 | §B.4(b) | **"Every host effect seam" is not enumerable in the spec.** What counts as a seam is host-architecture-specific (one HTTP client, or twelve integration SDKs each dialing out). The spec can require default-deny at the seam without being able to say where the seam is. | Spec Architect | Left host-defined by design — enumerating seams in protocol text would bind hosts to an architecture. The conformance seam probes the *effect count*, which is seam-agnostic. | Nothing; a known limit of black-box verification |
| G7 | §F | **Caveat 1's coverage claim is restored before any host is witnessed.** §F puts "idempotency requirements on side-effecting nodes" back in the status line when §B lands, which is at `Active`, whereas the witness lands at `Accepted`. Between those points the doc claims coverage that no host has demonstrated. | Steward | Acceptable because caveat 1 was *always* normative — §B repairs its mechanism rather than introducing a new promise. The status line describes what the document specifies, not what hosts do; `INTEROP-MATRIX.md` is where host claims live. | Nothing |
