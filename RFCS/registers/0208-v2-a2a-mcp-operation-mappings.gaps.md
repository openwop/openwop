# RFC 0208 — Gap register

These are the open design gaps found while authoring RFC 0208 (the v2 home for the A2A and MCP operation mappings). Each row is keyed to the RFC and has an owner and a resolution path. Every row begins with a disposition token (RFC 0166).

| ID | Section | Question / Missing Input | Owner | Resolution Path | Blocks |
| --- | --- | --- | --- | --- | --- |
| G1 | §A, Compatibility | The registry carries about 1,470 words of normative `rule` text in `spec/v2/interop-map.json`, and `check-core-budget.mjs` does not measure it, because the gate counts `.md` only. The practice has precedent (`errors.json`, `event-codemap.json`), but those rows are mostly enumerations, while these rows carry RFC 2119 sentences. | Spec Architect | `closed` — decided 2026-09-22 (steward decisions log D7): accepted under `overview.md` principle 4 (registers are data), on the `errors.json` / `event-codemap.json` precedent. Condition: the registry ships with its schema and `check-interop-map.mjs`, and core prose points to the rows and never duplicates their text. The RFC 0156 §B review may reopen it. | Nothing |
| G2 | Compatibility | The dual-major hazard. One A2A interface serves every OpenWOP major. v1 §D.2 requires `TaskNotFoundError` for a terminal task and v1 §D.7 pins the 1.0.0 statuses, while this RFC requires `UnsupportedOperationError` and 1.0.1. A dual-major host cannot satisfy both. | Compatibility Architect | `externally-gated:openwop-1481` — Merge Phase 2 P2-b (openwop#1481: the v1 correction plus the COMPATIBILITY §3 entry and the client dual-accept rule) before or with this RFC's spec PR. If P2-b slips, this RFC's spec PR waits. | Spec PR |
| G3 | Conformance | No v2 host serves an A2A interface or an MCP server mount. Committed bundles show v2-reference advertising `a2a` and `mcp` for seam-driven negotiation only (no `agentCardUrl`, `profiles` or `serverMount`); MyndHyve and openwop-app advertise neither family at major 2. Every behavioural row is `inapplicable` today. | Conformance Architect | `externally-gated:v2-a2a-mcp-interface-host` — openwop-app advertises `a2a` (`agentCardUrl`, `profiles: ["a2a-1.0"]`) and `mcp.serverMount` at major 2, reusing its v1 `a2aServer10.ts` / `routes/mcp.ts` — the smallest delta. Otherwise v2-reference builds both interfaces. A production deploy needs the steward's go. | `Accepted` |
| G4 | §B, Conformance | The six v1 current-profile MCP scenarios (`mcp-2026-07-28-discover`, `mcp-stateless-request`, `mcp-mrtr-roundtrip`, `mcp-cache-tenant-scope`, `mcp-extension-opacity`, `mcp-current-auth-boundary`) and the A2A 1.0 scenarios are major-1 only, and they cannot join `BOTH_MAJORS` because they gate on `.supported` seats. The invariants those scenarios witness (`mcp-cache-tenant-scoped`, `mcp-extension-no-authority`, `mcp-peer-no-authority-escalation`, `mcp-header-body-consistent`, `a2a-card-runtime-consistent`, `a2a-peer-no-authority-escalation`) have no major-2 test. | Conformance Architect | `transferred:conformance/src/scenarios/v2-mcp-mount-map.test.ts` — Port the scenarios into `v2-mcp-mount-map.test.ts` / `v2-a2a-operation-map.test.ts` legs reading v2 facets, and add each port to the invariant's `tests:`. | `Accepted` |
| G5 | Compatibility | No v1-dependent family can be homed to offset the +297 words. `a2a` and `mcp` are already resolved (their home is `interop.md`). The nearest candidate, `multiAgent`, whose facet is `executionModel`, is unrelated to A2A/MCP composition, and homing it would add its own text. The net stays at +297, under the +300 ceiling. | Spec Architect | `closed` — Recorded; no action. | Nothing |
| G6 | §C | `ListTasks` binds to `listRuns`'s result set, and `listRuns` scopes by tenant segment only (RFC 0182 §A.2). A2A §13.1 allows finer, principal-level models. A host whose authorization is finer than tenant would expose more through `ListTasks` than its own model allows, while still satisfying the letter of §C. | Security Architect | `transferred:SECURITY/threat-model-interop.md` — Tighten when v2 gains principal-scoped run listing. Until then §C is a ceiling, not a floor, and the note belongs in `SECURITY/threat-model-interop.md`. | Nothing today |
| G7 | §A (`a2a.card`) | Per-agent Agent Cards for the `/agents` inventory (RFC 0072/0074) carry their own isolation rules (public card vs tenant-scoped inventory). This RFC homes only the host card. | Spec Architect | `transferred:rfc-0202` — RFC 0202 owns the per-agent card as prose in `interop.md` §"Per-agent cards"; this RFC's `a2a.card` `supportedInterfaces[].tenant` row points there, and RFC 0202 relies on this RFC's Isolation paragraph instead of restating it. | Nothing |
| G8 | §E | The gRPC column of `a2a.errors` is unwitnessable. | G9 | §D | "Retained" versus "purged" is host retention policy. | G10 | §A (`mcp.meta`) | The `traceparent` / `tracestate` / `baggage` row homes only the existing v1 named mapping (propagated; never used for authorization). | G11 | §A (`mcp.mrtr`, `a2a.taskState`) | RFC 0199 (filed the same day) adds the `credential` interrupt, which projects to A2A `TASK_STATE_AUTH_REQUIRED` and to MCP URL-mode elicitation, and forbids form-mode secrets. Before this pass the draft map gave form mode to every waiting interrupt and said "no forward source" for `AUTH_REQUIRED`. | Schema Architect | `transferred:rfc-0199` — this RFC ships the `mcp.mrtr` InputRequiredResult row with form mode limited to flat, non-secret schemas (the upstream MUST), keys `a2a.taskState` by `(runStatus, interruptKind?)` with one default row per status, and defers every credential and authorization-required row to RFC 0199, whose spec PR adds `(waiting-input, credential) → auth-required`, the URL-mode clauses and the reverse note. | Nothing |
