# RFC 0206 — Gap register

Open design gaps found while authoring RFC 0206 (the case-canonical locale-key grammar). The rows are keyed to the RFC, and each has an owner and a resolution path.

| ID | Section | Question / Missing Input | Owner | Resolution Path | Blocks |
| --- | --- | --- | --- | --- | --- |
| G1 | §D / Compatibility | The v2 `content` and `i18n` families are still homed in `spec/v1/` (`spec/v2/declaration.json` `normativeText`). This RFC edits those v1 documents and writes no v2 core prose, so the v2 homing debt is unchanged and the core-word delta is 0. A full v2 home needs roughly 600 words: the §A coherence constraints, the section shape, `resolveSection`, the delivery endpoints and the §F security rules for `content`; `Accept-Language`, fallback and advertisement for `i18n`. The two families grant 400 words of cap, so homing both nets about +200. | Spec Architect | `transferred:spec/v2/declaration.json` — home both families together in a dedicated normative-home RFC (the RFC 0189/0190 procedure), after cheaper families have funded the cap. | Nothing in this RFC. |
| G2 | §A.2 | The grammar excludes RFC 5646 variants (`de-CH-1996`, `ca-ES-valencia`), extensions (`-u-ca-buddhist`), private use (`-x-`), `extlang` (`zh-yue`) and grandfathered tags. A host that negotiates one of these still cannot author content for it. | Schema Architect | `externally-gated:host-needs-variant-tags` — widen only when a host reports the need. Widening again is also a strict superset, but `resolveSection` would then need RFC 4647 §3.4's singleton-and-variant truncation. | Nothing. No committed host advertises such a tag. |
| G3 | §C.6 | `capabilities.{i18n,content}` keep the case-insensitive pattern `^[a-zA-Z]{2,3}(-[a-zA-Z0-9]{2,8}){0,3}$`. A non-canonical advertisement such as `pt-br` validates and can never be a `localizations` key. The SHOULD makes the hazard visible but does not remove it. | Compatibility Architect | `transferred:COMPATIBILITY.md` — tightening the capabilities pattern to canonical case rejects records that validate today (§2.2), so it waits for a major, or for RFC 0197's retirement rule if that rule ever covers a pattern narrowing (it does not as drafted). | Nothing. |
| G4 | Conformance | `openwop.requirement.0206.delivery-extended-locale` is gated on a host advertising a content locale outside the old subset. No committed bundle does: openwop-app and MyndHyve both advertise `es`, `pt-BR` and `fr`. | Conformance Architect | `externally-gated:host-extended-content-locale` — openwop-app (tier-1) or MyndHyve (tier-2) adds one content locale such as `es-419` or `zh-Hant`, then re-cuts. | `Accepted` on a host row. The corpus rows can carry `Accepted` without it; see the RFC's acceptance criteria. |
| G5 | §B.4 | `resolveSection` is "shared verbatim" between the spec pseudocode and the suite's TypeScript copy (`localized-content-delivery.test.ts:60`). Nothing mechanically checks that the two stay equivalent, and this RFC edits both. | Conformance Architect | `transferred:conformance/src/lib` — the §B.5 identity leg compares the suite copy to an embedded RFC 0103 copy, but not to the spec text. Consider extracting the algorithm into `conformance/src/lib/` and adding a doc-drift check. | Nothing. |
| G6 | §A.1 | `seo.ogLocaleAlternates[]` is typed as a BCP 47 tag, but Open Graph's `og:locale` convention is `language_TERRITORY` (underscore). The old grammar also rejected underscores, so the mismatch is not new. | Spec Architect | `transferred:spec/v1/localized-content.md` — decide whether a host renders `-` as `_` for OG output, or whether the field gets its own grammar (Unresolved question 1). | Nothing. |
| G7 | Implementation | The eight `spec-artifacts/` mirrors are exact-pinned by the conformance suite (`conformance/package.json`, `dist/spec-artifacts.lock.json`), so this change ships only in a coordinated `@openwop/spec-artifacts` + suite release. npm publish needs the steward's go. | Steward | `externally-gated:steward-release-go` — serialize with the other Phase 3 suite minors (arch-P3 M6). | The suite minor, not `Active`. |
