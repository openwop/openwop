# RFC 0163 — Gap register

Open design gaps discovered while authoring RFC 0163 (SCIM ⟷ SAML subject-linking hardening — the declarable link-key class + same-IdP trust-root MUST). Keyed to the RFC; each row has an owner and a resolution path. Gaps with no path are promoted to the risk register.

| ID | Section | Question / Missing Input | Owner | Resolution Path | Blocks |

| G1 | Proposal §A.1 / UQ2 | The enum `{opaque-idp, oid, immutable-id}` is the safe-class set derived from RFC 0159 §A.1 + UQ3. Is it complete, or is a fourth class (e.g. a directory-specific immutable GUID distinct from `oid`) wanted? | Spec Architect | Maintainer decision in the comment window; adding a member later is itself additive (allow-list enum growth) | — (non-blocking; enum is extensible) |
