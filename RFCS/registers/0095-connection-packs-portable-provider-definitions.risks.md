# RFC 0095 — Risk Register

Likelihood × Impact (H/M/L). Critical/High risks carry a named mitigation owner.

| ID | Risk | Likelihood | Impact | Score | Mitigation | Owner | Status |
|---|---|---|---|---|---|---|---|
| R1 | **Credential material leaks into a published connection pack** (an author pastes a client secret / token into a manifest and signs+publishes it to packs.openwop.dev). | M | H | **High** | §B.2 MUST-reject + the new `connection-pack-no-credential-material` SECURITY invariant + a public conformance scenario + a normative banned-property-name list (G5). Registry submission validation (RFC 0043) runs the same check at publish time, not just install. | Security Architect | Open |
| R2 | **SSRF via provider endpoints** — a malicious/compromised pack sets `authorize`/`token`/`reach.mcp.server.url` to an internal address; the host's OAuth dance or MCP call hits it. | L | H | **Med** | https-only pattern in schema; §B.3 fixes endpoints as manifest-declared (not runtime-derived); compose with RFC 0076 `host.safeFetch` / `assertPublicUrl` for the actual token POST + MCP connect. Pack signing (Ed25519) ties the manifest to an author. | Security Architect | Open |
| R3 | **Provider-id collision / squatting** — two packs claim `provider.id: "github"`; a typosquatted `community.evil.github` shadows the real one and points OAuth at an attacker. | M | H | **High** | §B.6 precedence rule (built-in vs installed) + reserved `core.*` scope for first-party providers + registry namespacing (G3/UQ4). Hosts SHOULD prefer `core.*` connection packs for well-known providers; surface `connection_provider_conflict` rather than silently choosing. | Compatibility Architect | Open |
| R4 | **MCP endpoint rot** — a Tier-1 pack's `reach.mcp.server.url` goes stale (ecosystem moves monthly); connections silently fail or the provider greys out. | H | M | **High** | Treat MCP URLs as re-verifiable registry metadata (G4); host SHOULD re-validate at install; non-normative "MCP endpoints are volatile" note. Keep the *manifest mechanism* stable even as *catalog content* churns (the catalog is a follow-up RFC, G7). | Conformance Architect | Open |
| R5 | **INTEROP-MATRIX drift** — hosts adopt the additive surface but stay on an older conformance suite, so the `connection-packs` column misrepresents reality. | M | M | **Med** | Gate every new scenario on `capabilities.packs.connectionsSupported`; a host that doesn't advertise it isn't measured against the column. Re-measure on suite bump. | Conformance Architect | Open |
| R6 | **Scope-model under-fit** — `groups`/`coarse`/`capabilities` can't represent a real provider's consent, forcing an out-of-band hack that fragments interop. | M | M | **Med** | Validate the 3 quirk providers (Stripe/Notion/Graph) against the schema before Active (G1); keep `scopeModel` extensible (enum can grow additively). | Schema Architect | Open |
| R7 | **Spec churn vs catalog churn coupling** — if Tier-1 packs ship inside this RFC (G7), every catalog update drags the normative RFC. | L | M | **Low** | Decision: ship the *mechanism* here, the *catalog* as a separate `core.openwop.connections.*` RFC/registry submission (Unresolved Q5 → recommend follow-up). | Spec Architect | Mitigated-by-design |
