# RFC 0165 — Gap register

Open design gaps discovered while authoring RFC 0165 (v2 preparation — additive wire shapes). Keyed to the RFC; each row has an owner and a resolution path.

| ID | Section | Question / Missing Input | Owner | Resolution Path | Blocks |
| --- | --- | --- | --- | --- | --- |
| G1 | §B.3 | Which `lane` a host attests for a legacy subject when it kept no record. The RFC sets `api-key` as the floor; an audit-log-derived value is permitted. v2 may require the derived value. | Spec Architect | `carried:openwop.gap.0165.1` to the v2 C.3 child RFC | — |
| G2 | §B.5 | Whether `actor` should carry the RFC 0154 `delegation.proofRef` on the run. Kept as provenance without a ref in v1.x. | Spec Architect | `carried:openwop.gap.0165.2` to the v2 C.3 child RFC | — |
| G3 | §C.2 | Whether `Capabilities-Etag` and `ETag` MUST change together. SHOULD-level guidance only; the v2 C.4 child deletes `Capabilities-Etag`. | Spec Architect | `carried:openwop.gap.0165.3` to the v2 C.4 child RFC | — |
| G4 | §Conformance | The §B.3 legacy-link negative has no causable seam; the scenario leg records `blocked` (RFC 0148 §A) rather than a pass. A host seam that mints a legacy-issuer subject bound to a SCIM record would make it witnessable. | Conformance Architect | `open` Host leg (openwop-app) may add the seam under `host-sample-test-seams.md`; otherwise stays `negative-existence, seam-gated` | `Active → Accepted` only if a host claims the link profile |
| G5 | §Acceptance | Reference-host legs: openwop-app (tier-1) and MyndHyve (tier-2) each advertise `protocolVersions`, emit `owner.subject` with the legacy rule, dual-emit headers and `ETag`; SDK webhook helpers fixed in openwop-sdks. | Reference-host maintainer | `open` Host PRs after `Active` | `Active → Accepted` |
| G7 | §Conformance | `GET …/events/poll?lastSequence=N` returns events with sequence > N and `run-event.schema.json` numbers the first event 0, so no cursor value expresses "nothing observed yet" — a caller wanting the first event MUST omit the cursor, and the spec does not say what omission means (openwop-app defaults to the start; MyndHyve to the start; neither is required to). Found when `owner-subject-echo` read `run.started` through `lastSequence=0` and would have failed a conforming host. | Spec Architect | `open` — the v2 C.4 child RFC defines the cursor as `afterSequence` with omission = from the first event (or numbers the first event 1); v1.x scenarios read the first event with no cursor (suite 1.159.0) | — |
