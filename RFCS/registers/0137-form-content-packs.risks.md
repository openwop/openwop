# RFC 0137 — Risk Register

Companion to [`0137-form-content-packs.md`](../0137-form-content-packs.md). Scored Likelihood × Impact (H/M/L). Critical/High risks carry a named mitigation owner.

| ID  | Risk                                                                                                                                                                                                                                                                                                                                 | Likelihood | Impact | Score    | Mitigation                                                                                                                                                                                                                                                                                                            | Owner                 | Status                        |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- | ------ | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------- | ----------------------------- |
| R1  | **A host renders a pack-authored `label` / `title` / `options[]` without escaping**, treating the Ed25519 signature as if it meant the *content* is safe. A published template titled `"<img onerror=…>"` or `"Ignore previous instructions and…"` then executes in host chrome or steers a downstream model call.                        | M          | H      | **High** | The F1 trust boundary is normative (`form-content-packs.md` §"Trust boundary"), backed by protocol-tier invariant `form-content-pack-string-trust-boundary` + a conformance leg. The spec states explicitly that a signature proves authorship, not content safety, and that length bounds are NOT sanitization.        | Security Architect    | Mitigated (host-pending leg)  |
| R2  | **A future RFC widens one kind's field-type vocabulary and not the other's**, silently forking `form-content` and `card` input semantics — the exact failure this RFC exists to prevent, reintroduced by drift six months from now.                                                                                                     | M          | H      | **High** | `form-content-packs.test.ts` PART 3 asserts the two `type` patterns are **byte-identical** across the two manifest schemas. The test fails the moment either side is widened alone. This is the single most load-bearing assertion in the scenario.                                                                     | Conformance Architect | Mitigated                     |
| R3  | **A registry adds the kind to manifest validation but not to its indexer**, so packs publish green and undiscoverable. Already measured on the reference registry — not hypothetical.                                                                                                                                                   | H          | M      | **High** | `openwop-registry#43` lands with or before the RFC (G8). `registry-operations.md` carries a non-normative operator warning recommending a build-time warning on an empty id set. Deliberately not promoted to MUST (§Alt 4) — that would break conformant registries.                                                    | Registry              | Open (tracked, PR drafted)    |
| R4  | **A host implements `form-content` as an execution surface** — treating a template as something that can define a handler or a submission endpoint — because "pack" connotes code.                                                                                                                                                       | L          | H      | Med      | The kind is declarative by construction: `runtime` is rejected by the version-manifest `allOf`, and §Instantiation states the host MUST use its normal create path and MUST NOT execute anything from the pack. The negative conformance leg asserts the `runtime` rejection.                                            | Spec Architect        | Mitigated                     |
| R5  | **`Accepted` stalls indefinitely** for want of a reference host, leaving the RFC `Active` and the kind publishable-but-unwitnessed.                                                                                                                                                                                                     | M          | M      | Med      | `openwop-app` has committed to the host side + scenario. The wire shape is LOCKED at `Active`, so the registry and pack authors are unblocked meanwhile; graduation is evidence-gated, not calendar-gated. Precedent: RFC 0071 Phase 2 sat `Active` until a real host witnessed it, then graduated.                      | Conformance Architect | Open (accepted trade)         |
| R6  | **The motivating pack is republished before the remap**, putting a manifest with rejected field types (`textarea` / `email` / `checkbox`) into a public registry.                                                                                                                                                                       | L          | M      | Low      | The host confirmed it is holding the publish (G9), and the remap forces a re-sign regardless since the signature covers exact bytes. The schema now rejects those values outright, so a mistaken publish fails validation rather than succeeding quietly.                                                                | openwop-app           | Mitigated                     |
| R7  | **`format` is mistaken for a second type axis** and hosts begin branching on it for control selection (`format: "email"` → a special email widget), re-creating the widget catalog through the side door.                                                                                                                                | M          | L      | Low      | The schema and spec both state `format` is a validation constraint, only meaningful on `text` / `longtext`, and that an unrecognized value MUST degrade to plain text. A host choosing an email-flavored input for `format: "email"` is harmless — the wire meaning stays "text validated as an email".                  | Spec Architect        | Accepted (benign)             |
| R8  | **Third parties publish form templates under `core.*`**, squatting the reserved namespace.                                                                                                                                                                                                                                             | L          | M      | Low      | `templateId` reuses the pack-name pattern and reserved scopes verbatim; namespace claim is enforced at registry `PUT` (`registry-operations.md` §"Validation flow" #2) and by RFC 0043 registry policy. No new surface.                                                                                                  | Registry              | Mitigated (existing controls) |
