# RFC 0202 — Gap register

Open design gaps discovered while authoring RFC 0202 (per-agent A2A Agent Cards). Keyed to the RFC; each row has an owner and a resolution path. Lands as `RFCS/registers/0202-per-agent-a2a-agent-cards.gaps.md`. No row is `open` (`docs/witness-baseline.json` `openGaps: 0`).

| ID | Section | Question / Missing Input | Owner | Resolution Path | Blocks |
| --- | --- | --- | --- | --- | --- |
| G1 | §Normative text | `agents` is not homed in v2. Its declared home is six v1 documents and 19 facets; the card rule written here is an `a2a` obligation in `interop.md`, which is already homed, so this RFC costs **+214** core words with no cap grant. A token v2 document naming 19 facets would pass the home gate and be the dishonest resolution RFC 0189's Motivation exists to end. | Spec Architect | `transferred:docs/normative-home-baseline.json` — `agents` stays in `v1Carried`; an honest v2 home is its own RFC, written last because it is the widest family (RFC 0190 G1). | Nothing. The budget holds (see the impl plan's running total). |
| G2 | §Compatibility | V1 gets no per-agent card. v1 `a2a-integration.md` §C and §E would carry the same rules, but every v1 MUST needs a v1 witness and no v1 host serves A2A 1.0 with a tenant-scoped inventory. | Compatibility Architect | `transferred:spec/v1/a2a-integration.md` — add a v1 half only if a v1 host asks for it; v1 is additive-only and retires at end-of-support. | Nothing. |
| G3 | §C | Roster entries (RFC 0086) are the more natural A2A agent — their `workflows[]` portfolio is `skills[]` — but they are not covered. | Spec Architect | `transferred:spec/v1/agent-roster.md` — a follow-up RFC applying §B–§D to `GET /agents/roster`, once one host witnesses this RFC. | Nothing. |
| G4 | §B.2 | "`R` MUST NOT encode a tenant, workspace, or principal" is only partly witnessable: the suite can look for identifiers the host discloses, not for ones it keeps private. | Conformance Architect | `transferred:conformance/src/scenarios/v2-a2a-agent-cards.test.ts` — the scenario states what it did not check in its header and the row's messages, not as a `partial-witness:` detail: that detail is reserved for a load-bearing clause that never ran and is refused by the acceptance predicate, while here the stability and disclosed-identifier clauses do run and are sabotage-proven (an `R` that embeds the tenant id fails the row). The RFC 0158 lesson still holds: the limitation is recorded, not hidden. | Nothing; §D.7 is the load-bearing non-disclosure clause and is fully witnessable. |
| G5 | §Invariant | `agent-card-no-tenant-leak` is named, not registered: registration waits for a committed bundle with `.identical-refusal` at `executed-pass`. | Security Architect | `transferred:SECURITY/invariants.yaml` — register in the PR that commits that bundle, re-deriving the count with `grep -c`. | `Accepted`. |
| G6 | §D.7 | No v2 host advertises both `a2a` and `agents`. The cross-tenant legs also need an operator-provisioned second principal and an agent only tenant B has. | Conformance Architect | `externally-gated:host-work` — MyndHyve (tier-2; `agents` with `installScope: "tenant"`) serving A2A 1.0 JSON-RPC under v2, or v2-reference gaining `/agents`. | `Accepted`. |
| G7 | §D.7 | Identical bodies are not identical latency; a timing channel remains. A2A v1.0.1 §13.1 is silent on it. | Security Architect | `transferred:SECURITY/threat-model-interop.md` — recorded as a residual threat, with a latency-equalization SHOULD left as Unresolved question 4. | Nothing. |
