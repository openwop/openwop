# RFC 0216 — Risk register

| ID | Risk | Likelihood | Impact | Score | Mitigation | Owner | Status |
| --- | --- | --- | --- | --- | --- | --- | --- |
| R1 | The list grows into a general escape: rows that are merely inconvenient to witness in production are added so a companion can witness them. | M | H | High | The list is a corpus file under a gate (§A.3): exact ids only, a closed anchor enum, agreement with Active/Accepted RFC tables, a scenario that actually gates on the anchor, and no floor scenario. Any RFC that extends it runs the RFC 0147 §A.6 full window (§A.4). The Draft's `witnessed-colocated` disposition, which would have stopped a row from blocking certification, was struck. | Conformance Architect | `mitigated` — by §A.3 and §A.4 once implemented. |
| R2 | An operator cuts the companion from the same image with different configuration that discovery does not show, such as a flag that disables the verifier's lifetime comparison. The companion passes, and production does not do what the row says. | L | H | Medium | §C.9(d) refuses every difference discovery exposes. §C.9(c) makes the operator's published key sign the companion. What remains is operator self-evidence, the same trust every self-cut bundle carries. | Security Architect | `accepted` — residual operator trust (Unresolved question 1, gap G3). |
| R3 | A companion that trusts a runner-held issuer is exposed to the internet, or given production data or credentials, and becomes an authentication bypass for whatever it can reach. | L | H | Medium | The GOVERNANCE text in §D forbids both. The openwop-app runbook binds to loopback only, with memory storage. This cannot be observed from the bundle, and the falsifiability row is `unwitnessable` and says why. | Security Architect | `mitigated` — by the operator obligation; it cannot be witnessed. |
| R4 | Verifiers on older suites reject bundles carrying `host.deployment`. | M | L | Low | This fails closed: an older verifier cannot read a companion as a served-host bundle. Consumers pin `@openwop/spec-artifacts`. | Compatibility Architect | `accepted` — the safe direction of RFC 0171 G6. |
| R5 | §C.9(c) read as "sign the companion with the production bundle key" would put that private key on the companion rig. | L | L | Low | §C.9(c) only needs a key that P's discovery publishes. The runbook uses a dedicated companion key whose private half lives only on the rig, so the production bundle key never signs a non-production bundle (clarified 2026-09-26). | Security Architect | `mitigated` |
| R6 | Production redeploys after the cut, so the pair describes an image that no longer serves. | M | M | Medium | The same is true of every production bundle today. GOVERNANCE already requires a flip to be checked against the live surface. The pairing forces the companion to match P's image, so both go stale together. | Conformance Architect | `mitigated` — by the existing live check at the flip. |
