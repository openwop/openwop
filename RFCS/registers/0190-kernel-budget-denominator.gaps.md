# RFC 0190 — Gap register

Open design gaps discovered while authoring RFC 0190 (the kernel budget's denominator and cap). Keyed to the RFC; each row has an owner and a resolution path.

| ID | Section | Question / Missing Input | Owner | Resolution Path | Blocks |
| --- | --- | --- | --- | --- | --- |
| G1 | §A | The per-family grant is **200 words** against a measured mean of **140.75** (four families, 563 words, five sections). That mean is drawn entirely from families with one or two facets. The remaining set includes `agents` (19 facets) and `aiProviders` (12), and a grounded model — ~110 base + ~20 per facet beyond the first — puts the remainder near 9,170 against 12,600 granted. If the real per-facet cost is higher than 20 words, the grant is too thin for the wide families even though the aggregate holds, and the self-funding property forces them to land LAST, when the cheap families have funded them. | Spec Architect | `transferred:scripts/check-core-budget.mjs` — re-measure after the next five families land, weighting by facet count rather than family count. The instrument is correct either way; only the constant is in question, and a constant is cheap to amend against evidence. | Nothing today. It bites only if the wide families cannot be funded by the narrow ones, which is observable before it is fatal. |
| G2 | §A | The cap reads `resolved` from `spec/v2/declaration.json` while the budget counts words — two different files, one number. A family could in principle be declared, grant 200 words, and later have its home refused by a tightened §B predicate, retroactively lowering the cap under prose already written. | Conformance Architect | `closed` — RFC 0191 cycle. The divergence was concrete, not hypothetical: `check-core-budget.mjs` counted a family as homed on `normativeText` being non-empty and not v1, so a family homed at `RFCS/0189-*.md` or a path that does not exist granted 200 words of cap while `check-v2-normative-home.mjs` hard-refused it. Inside `openwop:check` both run and the tree reds, but the budget is also a standalone npm script and reported a cap 200 too high. Fixed by applying the home gate's own class rule plus an existence check — today the two are computed in the same process from the same declaration, and the home gate runs in the same `openwop:check` invocation, so the window is one commit wide. Worth an explicit cross-check that the budget's `homed` equals the home gate's `resolved` count, rather than two independent derivations that agree by construction. | Nothing. It is a consistency risk between two gates, not a hole in either. |
| G3 | §B | `spec/v2/ext/` is now a co-pointer that contributes facet coverage only. Nothing checks that an ext document cited as a co-pointer is *about* the family citing it — the same bare-token weakness as RFC 0189 G1, one directory over. The `authorization`-against-thirteen-READMEs case is closed for the OBLIGATION predicate but not for facet coverage: a facet name appearing incidentally in an unrelated ext page still counts as covered. | Spec Architect | `transferred:scripts/check-core-budget.mjs` — resolve together with RFC 0189 G1, since both are the same predicate weakness and a fix for one should serve the other. | Nothing today; no core family cites an ext document. It becomes live the first time one does. |
