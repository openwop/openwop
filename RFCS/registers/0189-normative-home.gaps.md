# RFC 0189 — Gap register

| G1 | §B(c) | `namesKey` is a bare token match, so a family key that is a common English noun is satisfied by prose that merely uses the word. Measured against `spec/v2/core/*.md` with the gate's own predicate: `packs` has an obligation paragraph naming it in **7** documents — including `security-defaults.md` and `versioning.md`, which say nothing about the packs family's contract — and `idempotency` in **7**. Paragraph scope narrowed document scope but does not fix a common noun, and five of the families still undeclared (`packs`, `forms`, `replay`, `interrupt`, `connections`) are common nouns. A contributor under burn-down pressure can resolve `packs` against `security-defaults.md` and the gate will applaud. | Spec Architect | `closed` — RFC 0191. Four syntactic candidates were measured against all eleven declared families and a 24-case known-bad set; ALL FOUR either broke honest declarations (backticks fail five, headings fail six — honest prose names a family in WORDS: \"Connection Packs\", \"Form Content Packs\") or kept the loophole. The numbers were also worse than this row recorded: at 2.11.0 `replay` and `interrupt` each match NINE core documents, `idempotency` eight. Closed with a reciprocal marker instead of a predicate, which makes a false declaration explicit and reviewable rather than impossible — stated as such in RFC 0191 §B rather than claimed as soundness — the two obvious tightenings were measured and both misfire. Requiring the key in **backticks** fails 4 of the 7 families resolved today (`connections`, `toolHooks`, `toolCatalog`, `workflowChainPacks`): honest prose names a family in words ("connection packs"), not as a code token. A two-part variant (backticked anywhere in the document **and** named in the obligation paragraph) still fails `connections` and `workflowChainPacks`, and still resolves `packs` against `security-defaults.md`. Needs a predicate that ties the paragraph to a heading that names the family, sabotage-proven the way §C's three ratchets were — not a drive-by regex change. | Nothing today; it is a soundness ceiling on every future resolution, so it should land before the bulk of the remaining 61 families declare. |
| G2 | §E.2 | 61 families must find v2 homes inside the RFC 0174 §E.2 kernel budget, which `check-core-budget.mjs` reads over `spec/v2/core/*.md` only (non-recursive). At 2.9.0 the budget is **24,836 / 25,000** — 164 words free for 61 families. `spec/v2/ext/**` is a legal home under `homeClass()` and is **not** counted by the budget, and the precedent already exists (`spec/v2/ext/provider-idempotency/README.md` is supporting normative text for the **core** `idempotency` family). Left implicit, 62 authors each discover the escape valve independently and `ext/` silently becomes "core, but unbudgeted" — the 25,000-word cap defeated by directory name. | Spec Architect | `closed` — RFC 0190 §A. The `provider-idempotency` precedent claim in this row was WRONG: no core family declares an `spec/v2/ext/**` home, so the fix had zero retroactive cost. The hole was also worse than filed — an ext-only home needed no `core/` stub at all, and `spec/v2/core/<sub>/x.md` was the same hole one directory shallower. Resolved by making the budget measure what the home gate accepts, rather than by a granularity rule no gate could check — state the rule explicitly: a core family's base contract lives in `spec/v2/core/`; facet-level and operational detail MAY live in a `spec/v2/ext/<topic>/` supporting document co-pointed from `normativeText[]`, outside the kernel budget by design. Or raise the §E.2 budget. Either decision is fine; leaving it undecided is not. | The remaining 62 declarations — the budget as it stands cannot hold them. |
| G3 | §D | The burn-down decays `open` linearly to zero at v1 end-of-support, and `open = v1Dependent + undeclared` — but `v1Carried` families (`toolHooks`, `toolCatalog`) are explicitly tolerated past end-of-support by §D itself, which fails only if their target is deleted or its `Status:` banner changes. Counting a deliberately-tolerated family in a burn-down that must reach zero asks for work the RFC says is not required. | Spec Architect | `closed` — RFC 0190 §C, and the decision went the other way: `open` KEEPS counting `v1Carried`. This row's premise conflated §D's fallback with an exemption. `v1Carried` is hand-written and edited by the declaring PR, so excluding it would make 'add your family to v1Carried' a zero-work way to lower `open`. Closed in the CODE instead — the §D fallback is applied rather than printed, and `v1Carried` must now equal the computed v1-dependent set — decide whether `open` should exclude `v1Carried`. Two rows today; the arithmetic is small, but the schedule's meaning is not. | Nothing; it makes the schedule two families stricter than §D's own fallback. |
| G4 | §B(c) | A markdown TABLE is not one paragraph, but `split(/\n\s*\n/)` treated it as one — so an RFC 2119 keyword ANYWHERE in a table satisfied EVERY family named anywhere in it. Measured: `versioning.md`'s 18-axis disposition table is a single 20-line block; `multiAgent` (row 13) and `schemaVersions` (row 6) were both satisfied by the `MUST` in row 15, which is about `minClientVersion`. Both rows name `events.md` as their owner in their own Owner column, and `events.md` mentions neither family. The gate green-lit both declarations, with the RFC 0191 marker in place — so the marker's "explicit, local and reviewable" guarantee was being read against a reference table where the claim is contradicted three rows away. Eleven of the then-57 undeclared families had a table-only match waiting. | Spec Architect | `closed` — table rows are split into their own units. This is the ONLY tightening of the five measured (RFC 0191's four, plus this) that breaks no honest declaration: it strictly narrows, and none of the resolved families relies on a cross-row match. Sabotage-proved — the `multiAgent`/`schemaVersions` exploit is now refused by name, and all resolved families survive. | Nothing now; it was a live hole under burn-down pressure. |
| G5 | §B(b)/(c) | `-`, `_`, `.` and `/` are not word boundaries for a family key, but `namesKey` treated every non-alphanumeric as one — so a key was "named" by any token merely CONTAINING it. Measured at 2.13.0, six of the twenty families that satisfied §B(c) did so ONLY through this: `fs` ← "nodes are `fs-gated`"; `budget` ← `token_budget_exceeded`; `i18n` ← "see i18n.md"; `portability` ← the path `spec/v2/ext/portability/`; `workspace` ← `RunSnapshot.owner.workspace`. A further five matched through plain English homonyms (`cache` the verb, `production` the adjective, `content` in `content-free`). | Spec Architect | `closed` — the dot is ASYMMETRIC and that asymmetry is the rule: a FOLLOWING dot names a family only when what follows is a declared facet of it (`runList.maxPageSize` names `runList`), while a PRECEDING dot never does (`owner.workspace` is a field-path tail). `-`, `_`, `/` never bound. Facet coverage takes the mirror rule, since `family.facet` is a facet's canonical spelling. Sabotage-proved with the marker present, so the predicate is tested rather than RFC 0191's claim rule. It does NOT catch English homonyms — that is what the marker and a reader are for, as RFC 0191 §B says. | Nothing now. It caught that `a2a`'s own Step 1 resolution rested on a path match: `interop.md` genuinely homes it but never named it as a token, which is now fixed in the prose rather than by relaxing the rule. |
| G6 | §B.4 | `namesFacet`'s qualified form kept the FAMILY key's leading-boundary requirement, so it matched `limits.maxBudgetTokens` but not `Capabilities.limits.maxBudgetTokens` — the canonical spelling in v1 prose. `spec/v1/budget-policy.md` clamps to "the host ceiling (`Capabilities.limits.maxBudgetTokens` / `maxBudgetCostUsd`)": one sentence, a coordinated pair, and the gate covered the second and missed the first. G5's own closure note stated the intent correctly — *facet coverage takes the mirror rule* — but the implementation applied a family rule to a facet. | Spec Architect | `closed` — the qualified form now tolerates a dotted PREFIX on the family key, since `X.family.facet` still names the facet. Sabotage-proved: `Capabilities.limits.maxBudgetTokens` now covers, and `owner.workspace` still does not name the `workspace` family. | Nothing now. It was on the critical path for every one of the 49 undeclared families that carry facets. |
| G7 | §D | The end-of-support fallback tested the banner's STATE (a regex matching `Stable` or `FINAL`) rather than whether it CHANGED — and §D's own words are "deleted or its `Status:` banner changes". The two differ, and the difference was already live: `spec/v1/multi-agent-execution.md` has read `Status: Draft` since long before `multiAgent` was carried into it in 2.13.0, so on 2026-12-04 the daily job would have gone permanently red on a banner that never changed. Introduced by RFC 0190 §C, which implemented the fallback that RFC 0189 had only printed — one layer down from the defect it was fixing. | Spec Architect | `closed` — the banner is RECORDED at declaration time in `docs/normative-home-baseline.json` `v1Banners` and compared against. Sabotage-proved: an unchanged `Draft` banner no longer fails, and flipping `spec/v1/tool-catalog.md` `Stable → Withdrawn` is caught and printed was/now. A carried target with no recorded banner fails by name, so the map cannot silently go stale. | Nothing now; it would have fired on 2026-12-04. |
| G8 | §B(b) | G5 closed a PRECEDING dot but not a FOLLOWING one, and this register's own G5 row plus the gate's docblock CLAIMED otherwise — naming `i18n` ← "see i18n.md" as closed when it is not. The trailing boundary class excludes `-`, `_` and `/` but must leave `.` open for the `key.facet` arm, so `see i18n.md` still names `i18n` and `` `channelPresence.supported` `` still names `channelPresence`. | Spec Architect | `carried:openwop.gap.0189.8` — adding `.` to the trailing class was MEASURED and breaks EIGHT honestly declared families (connections, oauth, multiAgent, toolHooks, ...), whose real mentions are `key.<something>` where the something is not a declared facet. Closing it needs a predicate that distinguishes a facet reference from a filename, which is the same shape as G1 and should be solved with it. | Nothing mechanically; it is the largest remaining false-home generator, so every declaration's anchor must still be read by hand. |
| G9 | §D | The burn-down denominator (`open = v1Dependent + undeclared`) is STRICTER than the terminal predicate it schedules (`fatal = undeclared + uncarried + broken`) — at end-of-support a carried v1-dependent family is acceptable, but before it every such family still counts against the daily clock. A review recommended aligning them by changing the denominator to `undeclared`. | Spec Architect | `closed` — REOPENED AND REVERSED 2026-09-19. I first declined this, citing RFC 0190 §C's rejection of excluding `v1Carried` from `open`. §C's stated reason was that `v1Carried` is hand-written, so excluding it would make "add your family to v1Carried" a zero-work way to lower the count. THAT PREMISE WAS FALSIFIED BY WORK THAT LANDED AFTER IT: G7 requires `v1Carried` to EQUAL the computed v1-dependent set, and §B(b)/(c) + G5 require the v1 target to genuinely name the family and carry a 2119 obligation about it — the same predicate a v2 resolution must pass. Sabotage-proved: pointing `promptLibrary` at an unrelated v1 document is refused by name. So the hatch §C feared no longer exists, and I had applied §C's conclusion without rechecking whether its reason still held — the same error class this register exists to catch. The burn-down now measures `undeclared + uncarried`, which is literally the expression §D makes fatal; `openAtT0` re-seeded 68 → 66 (what `undeclared` was at t0). `v1Dependent` stays reported and unconstrained upward, because §C is still right that punishing the first honest declaration is what made silence cheapest. RFC 0190 §C already considered and rejected excluding `v1Carried` from `open`: "a fallback is what happens when you miss the target; it is not an exemption from the target." Changing the denominator now would reverse a documented decision in the direction that makes my own schedule easier, which is the definition of schedule-shopping. The tension is real and intended: §D is a safety net, not a target. The consequence — that the clock is expected to go red — is handled by SPLITTING it into its own workflow so a standing red cannot mask the unpublished-suite-tag alarm it used to share a job with. | Nothing. A true red is the signal; it now lives where it cannot drown another one. |
