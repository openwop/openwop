# RFC 0103 — Risk Register

Working document (not normative). Likelihood × Impact, each H/M/L. Critical/High-scored risks
carry a named mitigation owner. Per `RFCS/README.md`, open rows gate the `Accepted` flip and
must be swept.

| ID | Risk | Likelihood | Impact | Score | Mitigation | Owner | Status |
|----|------|------------|--------|-------|------------|-------|--------|
| R1 | **Draft content leaks via the public cache.** A draft section is written into a shared/public cache entry and served from a cached `published` response. | M | H | **High** | RFC §F MUST: public path serves `status:"published"` only; draft MUST NOT enter any public response or shared cache; cache key scoped so a draft can't be served from a cached published entry. Wire into the SECURITY-invariant coverage check + conformance scenario 6. | Security Architect | Open — confirm cache-key scoping in the host implementation + add the SECURITY invariant. |
| R2 | **Cross-tenant content disclosure / enumeration oracle.** A request for another tenant's `slug`/`pageId` reveals existence (different status code/timing) or returns content. | M | H | **High** | RFC §F MUST: all reads/writes tenant-scoped; cross-tenant id → the **same** `404` as nonexistent (no oracle). Conformance scenario 7 asserts indistinguishability. | Security Architect | Open — verify the 404-equivalence in conformance + host. |
| R3 | **A second locale mechanism creeps in** (e.g. a `?locale=` shortcut in a host implementation) violating the annex's "`Accept-Language` is authoritative" MUST-NOT. | M | H | **High** | RFC §C forbids `?locale=` and reuses the annex verbatim; Alternatives #3 records the rejection explicitly. Public delivery negotiates via header only. Keep the exclusion explicit; conformance asserts header-driven negotiation. | Spec Architect | Mitigated by design — hold the exclusion through implementation review. |
| R4 | **Capability dishonesty.** A host advertises `content.supportedLocales` it hasn't actually authored, or a set not ⊆ `i18n.supportedLocales`, so a client expects content that resolves to base. | M | M | **Med** | RFC §A MUST: `({baseLocale} ∪ content.supportedLocales) ⊆ i18n.supportedLocales`; `content.supported` requires `i18n.supported`. Conformance scenario 9 rejects the incoherent advertisement; INTEROP-MATRIX honesty rule applies. | Compatibility Architect | Open — wire scenario 9 + MATRIX honesty before `Accepted`. |
| R5 | **Merge-semantics drift across hosts.** Host A deep-merges nested locale fields, host B shallow-overlays → the same section resolves differently cross-host. | L | H | **Med** | RFC §C MUST: shallow overlay, nested objects replaced not deep-merged; `resolveSection` shared verbatim between host + conformance; deep merge is a named future opt-in (G-side Q6). Conformance scenario 4 (partial translation) pins the behavior. | Spec Architect | Open — confirm the single shared module + scenario 4. |
| R6 | **`Active` locks the shape before the reference host has exercised it.** A field/route name proves wrong once openwop-app implements, forcing a post-`Active` change. | M | M | **Med** | Surface is additive + capability-gated, so a post-`Active` refinement stays cheap (new optional field / additive amendment). Field/route names (`data`/`localizations`/`sectionOrder`/`baseLocale`/`supportedLocales`, `GET /v1/content/pages/{slug}`) coordinated with the host session up front; any change flagged as a blocking cross-host item before it lands. | Author | Open — keep the host (openwop-app) aligned on names through implementation. |
| R7 | **Third-party hosts adopt the additive surface but pin an old conformance suite → INTEROP-MATRIX drift** (standard additive-surface adoption lag). | M | L | **Low** | Gate new scenarios on `capabilities.content.supported` membership (soft-skip otherwise, matching the additive-surface precedent); remind in RFC §Conformance. | Conformance Architect | Open — standard mitigation. |
| R8 | **Last-write-wins on concurrent locale edits** (SQL read-modify-write of the `localizations` JSON) silently drops a concurrent editor's translation. | L | M | **Low** | Out of scope v1 (single-editor admin); RFC Implementation-notes states the LWW behavior explicitly; field-level concurrency is a future enhancement. Not a wire concern. | Reference-impl | Open — note in host docs; revisit if multi-editor lands. |
| R9 | **Open section bodies become an injection/validation gap.** `data`/`localizations` are open objects; a malicious or malformed section body passes envelope validation. | L | M | **Low** | Envelope is closed (`additionalProperties:false` on the wrapper); body shapes are the host/section-type's concern (G8); standard host-side input handling + FE text-node rendering (no innerHTML) on the consuming app. Not a wire concern. | Reference-impl | Open — reference-app code review. |
