# RFC 0132 — Risk Register

Companion to [`0132-anonymous-actor-authorization.md`](../0132-anonymous-actor-authorization.md). Working document (not normative). Likelihood × Impact each H/M/L; Score = combined severity. Critical/High rows name a mitigation owner.

| ID | Risk | Likelihood | Impact | Score | Mitigation | Owner | Status |
| --- | --- | --- | --- | --- | --- | --- | --- |
| R1 | **Over-grant: a host lets the anonymous actor inherit the authenticated default-on tool baseline** (ADR 0315-class), so a logged-out visitor drives an agent with full authenticated tool authority. | M | H | **High** | `anon-actor-no-default-baseline` invariant (§F) + `anonymous-actor-default-deny.test.ts`: the anon tool-catalog read (RFC 0078) MUST return only the explicit surface grant and fail empty; a non-granted call → `authorization.decided{allowed:false}`, no dispatch. Prose makes default-deny the load-bearing MUST-NOT. | Security Architect | Open — mitigated by design; behavioral test lands at `Active` |
| R2 | **Credential confused-deputy: a tenant BYOK credential attached to a visitor-triggered egress** → exfiltration to an attacker destination. | M | H | **High** | `anon-actor-egress-ssrf-guarded` (§F) composes RFC 0079 `egress-credential-audience-bound` + RFC 0076 §B SSRF guard: anon egress defaults `downgraded`/`denied`, credential only if in-audience AND host-permitted. `anonymous-actor-egress-guarded.test.ts` (out-of-audience → denied, credential NOT attached). | Security Architect | Open — mitigated by composition; test lands at `Active` |
| R3 | **Secret / cross-tenant reach: an anon read tool surfaces a secret or another tenant's data.** | M | H | **High** | `anon-actor-no-secret-reach` (§F, both tiers) — SR-1 canary + CTI-1 cross-tenant fail-closed (`run_forbidden`); `anonymous-actor-no-secret-reach.test.ts` plants a BYOK canary in the surface tenant and asserts it never surfaces + a cross-tenant read fails closed. Read tier is normatively no-egress / no-secrets. | Security Architect | Open — mitigated by design; test lands at `Active` |
| R4 | **Ungated write abuse: a public surface performs an unbounded, un-approved durable write/egress** (spam, resource exhaustion, data poisoning) at visitor scale. | M | H | **High** | `anon-actor-write-egress-gated` (§F): the `bounded-write-egress` tier is permitted ONLY behind a mandatory control (HITL/approval OR hard rate-limit + per-session cap), advertised via `writeEgressControls`; ungated → denied. Schema §B.2 conditional forbids a control-less write tier. `anonymous-actor-write-gated.test.ts`. | Security Architect | Open — mitigated by design + schema; test lands at `Active` |
| R5 | **De-anonymization / cross-linkability: a host keys the anon actor on IP / fingerprint or reuses the id across sessions**, turning an "anonymous" actor into a tracked identity (privacy + regulatory exposure). | M | H | **High** | `anon-actor-audit-opaque` (§F) + §A.1–A.3 normative: identifier MUST be opaque, host-minted, per-session-ephemeral, non-cross-linkable, non-PII; audit record carries no PII. §A.2 forbids id reuse across sessions. Continuity-token pressure explicitly parked (Unresolved-Q2 / G6). | Security Architect | Open — mitigated by design; opacity test lands at `Active` |
| R6 | **Prompt injection at scale: the untrusted visitor message drives a tool-enabled anon dispatch** (indirect injection → coerced tool call). | M | M | **Med** | Untrusted visitor input is fenced (`<UNTRUSTED>`, threat-model-prompt-injection.md T1) and placed as the user turn (reference host already does this); the default-deny grant + the write-gate + the secret/cross-tenant floor bound the blast radius of any successful coercion. New A-ANON adversary row (§F). | Security Architect | Open — bounded by the §C floor |
| R7 | **Hollow advertisement: a host advertises `bounded-write-egress` without actually enforcing a control** (fail-open masquerading as fail-closed). | L | H | **Med** | §B.1 truthful-advertisement MUST + `OPENWOP_REQUIRE_BEHAVIOR=true` hard-fail; §B.2 schema conditional makes a control-less write tier schema-invalid at the advertisement layer, before any behavior test. | Conformance Architect | Open — schema + behavioral guard |
| R8 | **Third-party hosts adopt the additive block but stay on an older suite → INTEROP-MATRIX drift** (advertise `anonymousActor`, unverified behavior). | M | M | **Med** | All behavioral scenarios gate on `anonymousActor.supported` + soft-skip / `OPENWOP_REQUIRE_BEHAVIOR` hard-fail; register the row in `coverage.md` §"Capability-gated scenarios"; the `### Anonymous-actor authorization` INTEROP-MATRIX section tracks per-host advertisement vs verified behavior. | Conformance Architect | Open — standard capability-gating posture |
| R9 | **Scope creep into A2A / cross-host anonymity** widens the RFC's threat surface mid-authoring. | L | M | **Low** | §E + Unresolved-Q3 (G5) keep the anonymous actor a *local* public-surface concept; the A2A-forwarded case is an explicit follow-on, not in this RFC's normative surface. | Compatibility Architect | Open — scoped out by design |
| R10 | **Reference-host implementation slips**, leaving the behavioral invariants shape-only indefinitely (the RFC 0079 "reference-impl deferred" pattern stalling). | M | M | **Med** | The reference path is short (openwop-app's gateway already resolves surface→tenant, origin-gates, fences input, dispatches via a managed key — it just adds tools + the grant model). Track under the chat-first-port A5 unit; `Accepted` is explicitly gated on a reference host wiring a tool-enabled public surface (G9). | Reference host (openwop-app) | Open — tracked, path identified |
