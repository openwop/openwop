# RFC 0070 — Risk Register

Scored Likelihood × Impact (H/M/L). Critical/High risks require a named mitigation owner and target resolution date.

| ID | Risk | Likelihood | Impact | Score | Mitigation | Owner | Status |
|---|---|---|---|---|---|---|---|
| R1 | **Schema-bomb / ReDoS via distributed artifact schemas.** A published artifact-type pack ships a JSON Schema with pathological `$ref` recursion or a catastrophic-backtracking `pattern`; the engine compiles it (Ajv) and is DoS'd at workflow-register or validate time. | M | H | **High** | Bound schema size, `$ref` depth, keyword count at registry `PUT`; reject ReDoS-prone patterns; compile in a time-boxed sandbox. Add a protocol-tier MUST-NOT invariant + matching public conformance test in `SECURITY/invariants.yaml` (forces `openwop:check` step 9). Extend `threat-model-node-packs.md`. | Security Architect | Open — target before `Active` |
| R2 | **Prompt injection through card templates.** Card `prompt.template`/`systemPrompt` interpolate workflow inputs via `placeholderMapping`; untrusted input reaches the LLM and can exfiltrate or coerce structured output. | M | H | **High** | Mandate `EnvelopeMeta.contentTrust='untrusted'` propagation for card-input-derived content (`ai-envelope.md` §trust boundary); document in `threat-model-prompt-injection.md`; conformance scenario asserting trust-tag propagation through `chat-card-pack-execution`. | Security Architect | Open — target before Phase 2 `Active` |
| R3 | **Cross-host artifact-type drift / INTEROP-MATRIX dishonesty.** Hosts adopt the additive surface but stay on an older conformance suite; matrix claims support that isn't behavior-graded. | M | M | **Med** | Gate every behavior scenario on the capability flag; keep behavior grade `host-pending` until a reference host passes; require matrix column + `OPENWOP_REQUIRE_BEHAVIOR` enforcement per `conformance/coverage.md`. | Conformance Architect | Open |
| R4 | **`registered: false` silently masks a schema mismatch.** A host treats an unregistered `artifactType` as valid (escape hatch) when the author *intended* it registered but typo'd the id — no error surfaces. | M | M | **Med** | Emit `registered: false` explicitly so tooling can warn; recommend (SHOULD) host logs an unresolved-artifact-type warning; conformance asserts the flag is set correctly. | Compatibility Architect | Open |
| R5 | **Scope creep toward "canvases."** Reviewers push to add viewers, field widgets, or canvas-pack rendering, re-importing the UI-coupled surface `positioning.md` forbids. | M | M | **Med** | RFC §Proposal + Alternative 3 + the spec doc's "Why this exists" state the boundary explicitly; `inputs[].type` is a closed portable enum; `rendering`/`exportFormats` are advisory hints only. Reject UI-coupled additions in comment window. | Spec Architect | Open |
| R6 | **Two pack kinds in one RFC stall each other.** Phase 2 (cards) blocks on Phase 1 (artifact types); bundling risks the whole RFC stalling on Phase 2's open questions (G4, G8, G9). | M | M | **Med** | RFC is explicitly phased; Phase 1 reaches `Active`/`Accepted` independently; `/plan 0070` split milestone tracks; Phase 2 may be deferred or split to a follow-up RFC if it stalls. | Spec Architect | Open |
| R7 | **No reference host implements either kind** (agent-runtime gap). `Accepted` cannot be reached without a consumer; risk of a perpetually-`Active` RFC describing surface nobody runs. | H | M | **Med** | Acceptance criteria explicitly permit deferring reference-host implementation; target the in-memory reference host for at least Phase 1 `store`; otherwise land at `Active` and track in `ROADMAP.md`. | Conformance Architect | Open |
| R8 | **Single-maintainer governance.** A normative pack-kind addition merges under one steward-maintainer before the non-steward tripwire fires, weakening vendor-neutrality claims. | M | L | **Low** | Honor full RFC comment window; solicit MyndHyve (the adopter whose pattern this generalizes) as external reviewer; record in `MAINTAINERS.md`/`GOVERNANCE.md` decision log. | David Tufts | Open |
| R9 | **`exportFormats` becomes a de-facto codec spec.** Without a controlled vocabulary, hosts disagree on what `"pdf"`/`"pptx"` mean, and pressure mounts to specify byte production — violating the no-renderer boundary. | L | M | **Low** | Keep `exportFormats` as advisory identifiers; if a vocabulary is needed (G5), define identifiers only, never byte semantics. | Spec Architect | Open |
