# RFC 0173 — Gap register

Open design gaps discovered while authoring RFC 0173 (v2 security defaults; RFC 0167 child C.6). Keyed to the RFC; each row has an owner and a resolution path.

| G1 | §D.1 | RFC 0035 (Active, Parked on a non-steward fencing host) is superseded by this child's `packs` obligation at the cut; until then it stays Parked and its §B probes are the eight `sandbox-*` scenarios this RFC binds to execution. | Steward | `closed` 2026-09-18 — 0035 flipped `Superseded` with a forward pointer in **RFC 0173's own `Active → Accepted` PR**, exactly as this row required, which is also where this RFC's `Supersedes` cell stops beginning with `—`. Corrected 2026-09-18: the earlier wording said "in the Phase 3 PR", which read as a standalone step and is not safe as one. RFC 0035 is still the cited authority for four v1 error codes (`sandbox_memory_exceeded`, `sandbox_timeout`, `sandbox_capability_denied`, `sandbox_escape_attempt` — `rest-endpoints.md`), seven **protocol-tier** `node-pack-sandbox-*` rows in `SECURITY/invariants.yaml`, and seam §8 in `host-sample-test-seams.md`. v1 is served until 2026-12-04 (`check-removal-dates`), so retiring that authority before its replacement is `Accepted` would leave live normative text pointing at a terminal RFC. RFC 0001 fixes the timing — `Superseded` is flipped **when the replacement reaches `Accepted`** — and RFC 0174 §A.1 requires both edits in one PR. The `(**Parked**)` annotation must be stripped in the same edit: `rfc-lifecycle-coherence` refuses a Parked RFC that is not `Draft` or `Active`. | RFC 0173 `Accepted` |
