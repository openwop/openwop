# RFC 0140 — Gap register

Filed retroactively (2026-08-08), after the RFC reached `Accepted` without one. `RFCS/README.md` §Registers requires a register sweep at the `Accepted` flip, and an `Accepted` RFC with silently-open rows is a process violation — so the rows below are the sweep, recorded rather than backdated. Every one is either closed or explicitly carried forward.

| ID | Section | Question / Missing Input | Owner | Resolution Path | Blocks |
|---|---|---|---|---|---|
| G1 | §B requirement 5 | ✅ **CLOSED.** The default-deny effect-seam guard exists in the reference host: ADR 0531 (run-scoped `AsyncLocalStorage` context + `assertEffectAllowed`), widened by ADR 0533 from 3 call sites to the shared egress dispatcher covering ~20 node-reachable outbound paths, with payment and cross-host dispatch seams guarded individually. | Steward | Closed at the witness. | — |
| G2 | §Conformance | **The happy path is not directly witnessed.** The scenario rests on the fail-closed asymmetry, which is unforgeable — but the RFC's original argument was right that an event-log assertion cannot distinguish "suppressed" from "fired and recorded identically" on the **happy** path. A host that fails closed correctly *and* re-fires on a recorded node passes today. | Conformance Architect | `carried:openwop.gap.0140.2` forward.** openwop-app implements an effect-counter seam (`GET /v1/host/sample/replay/effect-count`, ADR 0533) that closes it; a gated strengthening leg can be added when a second host has the seam. Unlikely-but-possible failure mode, stated rather than implied. | Nothing; bounds what a green run proves |
| G3 | §B requirement 5 | **Classification and the guard can mask each other.** A fixture node that is both classified side-effecting AND routed through a guarded seam stays green when either mechanism alone is disabled — only disabling both reds it. The suite therefore does not independently witness requirement 5(b). | Conformance Architect | `carried:openwop.gap.0140.3` forward.** Inherent: a fixture whose node is *unclassified* would not be suppressed on a conformant host either, so the suite cannot construct the discriminating case from the wire alone. The guard's independent evidence is host-side (openwop-app `test/run-effect-context.test.ts`, which drives an unclassified node into a replay). | Nothing; bounds what the suite alone proves |
| G4 | §B requirement 5 | **Three node-reachable effect paths remain unguarded in the reference host** — `deliverToSubscribers` (webhook fan-out), `s3Blob.put`, `openSearchSearch`. The webhook case is the substantive one: host-level fan-out with no node to fail closed, running in a subscriber whose throws the event log swallows, so a guard there would suppress **silently**. | Host owners | `carried:openwop.gap.0140.4` forward** as an openwop-app follow-up. Bounds the reference host's `recorded-outcome` claim to the guarded seam set. | Nothing; bounds the reference host's advertisement |
| G5 | §A | **Declaring the `replay` block retroactively schema-validates existing readers.** Six conformance scenarios and two profile predicates (`profiles.md` §`openwop-replay-fork`, `agent-platform-profile.md`) previously read an unvalidated object. | Schema Architect | `closed` at landing: the block is declared **open** with every field optional, per `COMPATIBILITY.md` §2.1 (RFC 0094 — server-emitted shapes MUST NOT be closed). Survey `INTEROP-MATRIX.md` advertisements if a host is ever reported failing validation. | Nothing today |
| G6 | §D | **`branch` remains unsuppressed and unwitnessed.** The asymmetry is deliberate, but no scenario asserts it, so "branch re-fires" is documented behavior with no test. | Spec Architect | `carried:openwop.gap.0140.6` The §`branch` mode caution makes it explicit for operators. A scenario would assert a *permission*, not a requirement — deliberately not built. | Nothing |
| G7 | §B requirement 5(b) | **"Every host effect seam" is not enumerable in the spec.** What counts as a seam is host-architecture-specific (one HTTP client, or twelve integration SDKs each dialing out). The spec can require default-deny at the seam without being able to say where the seam is. | Spec Architect | `carried:openwop.gap.0140.7` Left host-defined by design — enumerating seams in protocol text would bind hosts to an architecture. | Nothing; a known limit of black-box verification |
| G8 | §B | **Out-of-process pack execution is uncovered.** Run-scoped ambient state (`AsyncLocalStorage` in the reference host) does not survive a process/worker boundary, and widening the seam set makes that gap larger, not smaller. | Host owners | `carried:openwop.gap.0140.8` forward.** A host that sandboxes node execution out-of-process MUST re-establish the context on the host side of that boundary; noted in §Implementation notes. | Nothing; a named host obligation |
| G9 | §Motivation | **How many hosts actually violate caveat 1 is unmeasured.** The claim is argued from the mechanism, not surveyed; only openwop-app's behavior is known. | Compatibility Architect | `carried:openwop.gap.0140.9` The argument holds regardless — the named mechanism is provably inoperative across a fork. The count affects how loudly the correction is announced, not whether it is right. | Nothing; affects release notes |
