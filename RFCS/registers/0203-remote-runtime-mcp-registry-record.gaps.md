# RFC 0203 — Gap register

Open design gaps discovered while authoring RFC 0203 (inline MCP Registry record on the `remote` runtime; `nodePackRuntimes` v2 home). Lands as `RFCS/registers/0203-remote-runtime-mcp-registry-record.gaps.md`. No row is `open`.

| ID | Section | Question / Missing Input | Owner | Resolution Path | Blocks |
| --- | --- | --- | --- | --- | --- |
| G1 | §A.2 | The subset is pinned to `server.json` `2025-12-11`. The registry's next dated release (a Draft already widens `url` to a leading template variable) may add members or loosen patterns; our closed subset then lags, and a publisher copying a newer record verbatim is refused. | Schema Architect | `transferred:schemas/v2/node-pack-manifest.schema.json` — on each upstream release, vendor the new schema, re-run the subset leg, and widen `$schema` to an enum in an additive RFC (Unresolved question 3). | Nothing. |
| G2 | §Compatibility | V1 manifests do not gain `mcpServer`. The v1 tree is frozen through the overlap (`packs.md` §"The registry tree"), and a v1 field would need a v1 witness. | Compatibility Architect | `transferred:schemas/node-pack-manifest.schema.json` — no v1 half unless a v1 publisher asks; v1 retires at end-of-support. | Nothing. |
| G3 | §C.7 | The restated `wasm` MUSTs have witnesses only at major 1 (`wasm-pack-abi-version-rejection`, `-memory-cap`, `-load`, … in `conformance/scenario-majors.json`). The v2 home is now honest prose over a family whose behavioural witnesses do not run against v2 hosts. | Conformance Architect | `transferred:conformance/scripts/generate-scenario-majors.mjs` — add the six `wasm-pack-*` files to `BOTH_MAJORS` once each is checked version-agnostic (no `/v1/` literal paths), in the same suite minor as this RFC's coherence test. | Nothing for this RFC's own rows (corpus-witnessed). |
