# RFC 0197 — Gap register

Open design gaps found while writing RFC 0197 (v2 surfaces are retired, never reshaped). Each row is keyed to the RFC and has an owner and a resolution path. Each row is mirrored in `spec/v1/gaps.json` as `openwop.gap.0197.<n>`.

| G1 | §C.7 | MyndHyve's committed v2 bundle (suite 2.35.1, 2026-09-22) advertises 38 families `stable` that `spec/v2/declaration.json` calls `experimental`. §C makes that non-conforming for bundles cut on the first suite release that ships this RFC. | MyndHyve (host) | `externally-gated:myndhyve-recut` — decided 2026-09-22 (steward decisions log D1): §C is a MUST for bundles cut on the first suite release that ships RFC 0197; existing committed bundles are reported, not failed (the RFC 0148 measurement precedent). No family is promoted here; promotion is a per-family evidence decision by RFC (§C.9). The owed item is MyndHyve's re-cut with `status: "experimental"` and a future `until` on the 38 families. | The Accepted evidence bar's MyndHyve leg. |
| G2 | §A.2 R3 | The registry leg is only as good as `evidence/cross-repo-manifests.json`, which is generated from a sibling checkout the gate cannot see. A stale checkout undercounts. The local registry checkout is at `d0d4700` with CORPUS_TAG v2.2.3, 30+ minors behind. The 30-day freshness bound limits the damage, but it cannot prove the checkout was current when the census ran. | Conformance Architect | `transferred:scripts/generate-cross-repo-evidence.mjs` — record the registry commit and its commit date next to the census, and have R3 require that the registry commit date is no older than the census's own date minus 7 days. | Any retirement of a manifest-side value (the first one: connection-pack `sse`). |
| G3 | §A.1 | `spec/v2/surface-baseline.json` is regenerated by the release PR. | G4 | §A.3 | The host half of "readers keep accepting retired persisted shapes" is unwitnessable: a black-box suite cannot put a pre-retirement member into a run log that it creates after the retirement.
