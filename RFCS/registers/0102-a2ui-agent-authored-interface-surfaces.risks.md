# RFC 0102 — Risk Register

Working document (not normative). Likelihood × Impact, each H/M/L. Critical/High-scored
risks carry a named mitigation owner. Per `RFCS/README.md`, open rows gate the `Accepted`
flip and must be swept.

| ID | Risk | Likelihood | Impact | Score | Mitigation | Owner | Status |
|----|------|------------|--------|-------|------------|-------|--------|
| R1 | **UI-redress / deceptive surface.** A malicious (or untrusted-A2A) agent crafts a surface whose labels misrepresent the action — e.g. a "Confirm time" button that resolves an approval to "send to all." | M | H | **High** | Closed catalog renders labels as plain text (no markup, `a2ui-surface-no-code-exec`); actions confined to resume/exchange (`a2ui-action-confinement`); untrusted surfaces cannot advance an `approval` gate (`untrusted_content_blocks_approval`, existing). The resume value is still subject to the interrupt's own answer schema + downstream action governance. | Security Architect | Open — confirm the existing approval-block fully covers the deceptive-label case in threat review (links G6). |
| R2 | **Naive host inlines a credential or PII into a surface payload** (e.g. pre-filling a field from a secret-bearing context). | L | H | **Med** | SR-1 redaction harness walks the full payload graph (`ai-envelope.md` §"Redaction") — already mandatory for all envelopes; add a redaction example for `ui.a2ui-surface` in spec; no new code path. | Security Architect | Open — add the worked redaction example to spec text. |
| R3 | **Client-render conformance gap** (G3): hosts advertise the kind but the suite can't prove their renderer is safe, since OpenWOP conformance is server-side. INTEROP-MATRIX could imply more assurance than the suite delivers. | M | M | **Med** | Record `no-code-exec` / `action-confinement` as **suite-version requirements w/ a reference-app probe**, not server MUSTs; the MATRIX column reflects emit/advertise only; `coverage.md` states the split explicitly. | Conformance Architect | Open — wire the split before `Accepted`. |
| R4 | **Catalog-version drift across hosts** — host A emits a 0.9.1 surface, host B renders an older catalog; or a host bumps catalogs and can't render historical surfaces on `:fork`. | M | M | **Med** | `catalogVersion` REQUIRED in payload (§A) so the renderer can detect mismatch and degrade fail-closed; resolve the registry-vs-free-string question (G2); cross-host re-validation against the local catalog (§A.2). | Spec Architect | Open — tied to G2/Q2. |
| R5 | **Scope creep toward A2UI v1.0 client-to-server RPC.** Pressure to "just add" the RPC channel collapses the security story (a new agent→host control channel). | M | H | **High** | RFC explicitly excludes v1.0 RPC (Alt #4); actions confined to resume/exchange by normative MUST (§A.3). Any RPC must be a separate RFC with its own threat model. | Spec Architect | Mitigated by design — keep the exclusion explicit through the comment window. |
| R6 | **Third-party hosts adopt the additive kind but pin an old conformance suite → MATRIX drift** (the standard additive-surface adoption lag). | M | L | **Low** | Gate the new scenarios on `supportedEnvelopes` membership (soft-skip otherwise, matching the RFC 0055 reliability-scenario precedent); remind in RFC §Conformance. | Conformance Architect | Open — standard mitigation. |
| R7 | **Dependency on an external, pre-1.0 spec.** A2UI is v0.9.1 (v1.0-candidate); the pinned catalog shape may shift before A2UI 1.0. | M | M | **Med** | Pin a specific A2UI version (G5); carry `catalogVersion` so a future bump is additive; OpenWOP closes only the envelope wrapper, not A2UI internals (G7), isolating churn. Treat as a **Parked**-able tripwire if A2UI 1.0 lands mid-window. | Author | Open — pin version when opening comment window. |
| R8 | **Renderer becomes an injection vector via a flawed component implementation** (the catalog is safe by contract, but a buggy native widget mis-handles untrusted field text). | L | M | **Low** | Standard FE XSS discipline in the reference renderer (text nodes, not innerHTML); covered by the `openwop-app` build gates + a render-probe test; not a wire concern. | Reference-impl (ADR 0051) | Open — reference-app code review. |
