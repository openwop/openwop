# RFC 0098 — Risk Register

Likelihood × Impact (H/M/L). Critical/High risks carry a named mitigation owner.

| ID | Risk | Likelihood | Impact | Score | Mitigation | Owner | Status |
|---|---|---|---|---|---|---|---|
| R1 | **Credential material in a bundle** — an exporter (or a competitor-import adapter) writes a client secret / token / SAML cert into a `connection-ref` payload, and it travels in plaintext. The single highest-severity failure. | M | H | **High** | §E(1) MUST-NOT + a **mandatory** conformance scenario (no-secret-values) + a SECURITY invariant `import-bundle-no-credential-material` (mirror RFC 0095 `connection-pack-no-credential-material`): banned-property-name list, rejected `422` on export and import. `secretsToRebind` reports refs only. | Security Architect | Open |
| R2 | **Destructive overwrite** — a non-idempotent import clobbers existing destination estate (overwrites a live agent/schedule) instead of skip/update. | M | H | **High** | §E(3) idempotency MUST + the mandatory `dryRun` plan (§E(2)) showing creates/updates/skips/conflicts **before** any write; per-kind idempotency key (G5); `conflict` items surfaced, never silently overwritten. | Compatibility Architect | Open |
| R3 | **Cross-tenant ownership leak** — an imported entity retains the source principal's identity/access, granting the importer (or the source) unintended cross-tenant reach. | L | H | **Med** | §E(4) MUST re-own every imported entity to the caller's RFC 0048 identity; `source.originPrincipal` is informational and MUST NOT grant access; conformance scenario asserts re-ownership + isolation (compose RFC 0048 isolation tests). | Security Architect | Open |
| R4 | **SSRF / egress via imported endpoints** — a malicious bundle's `connection-ref`/pack points an authorize/token/MCP URL at an internal address; the destination host's OAuth dance or fetch hits it. | L | H | **Med** | Reuse RFC 0079 egress policy + RFC 0076 `host.safeFetch`/`assertPublicUrl` at the destination; imported executable behavior SHOULD stage as RFC 0096 proposals (G2) rather than activate; optional bundle signing (G1). | Security Architect | Open |
| R5 | **Partial-import inconsistency** — apply fails mid-graph (item 7 of 12), leaving a half-imported estate with dangling `dependsOn` edges. | M | M | **Med** | Topological apply (§C) + per-item `ImportResult` (`created|updated|skipped|failed`) so the operator sees exactly what landed; reapply is idempotent (R2) to converge. Consider transactional apply as a host MAY. | Compatibility Architect | Open |
| R6 | **Unsigned-bundle tampering** — a bundle is modified in transit between hosts (or by a malicious adapter) and the destination imports altered behavior. | L | M | **Low** | Optional detached signature now; mandatory-for-cross-host in a follow-up (G1); re-ownership (R3) + staged activation (G2) limit blast radius even unsigned. | Security Architect | Open |
| R7 | **INTEROP / capability dishonesty** — a host advertises `portability.import` but not `dryRun`, so an operator can't preview before a destructive write. | L | M | **Low** | §A: `portability.dryRun` MUST be true if `import` is true; §E(2) MUST offer the no-write plan; conformance gates on the capability and asserts dry-run is read-only. | Conformance Architect | Open |
| R8 | **Adapter scope creep** — competitor-format adapters drift into normative spec text, coupling the wire to proprietary formats that churn. | L | M | **Low** | §Alternatives + G8: adapters are tooling, explicitly non-normative; the RFC standardizes only the openwop bundle + import mechanism. | Spec Architect | Mitigated-by-design |
