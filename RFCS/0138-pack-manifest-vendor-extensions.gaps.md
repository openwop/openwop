# RFC 0138 — Gap register

Open questions, deferred decisions, and missing inputs beyond the in-template
Unresolved questions. Each gap has an owner and a resolution path. A gap with no
path is promoted to a Risk (`0138-pack-manifest-vendor-extensions.risks.md`).

| ID | Section | Question / Missing Input | Owner | Resolution Path | Blocks |
|---|---|---|---|---|---|
| G1 | Proposal | **Namespace collisions are unarbitrated.** Two vendors may both claim `x-canvas`. `host-extensions.md` recommends `private.<host>.*` for host-internal namespaces, which avoids it for the disciplined, but nothing enforces discipline. | Spec Architect | Escalate to a registered-extensions registry (RFC 0138 §Alternatives, item 4) **only if a real collision is reported**. Building it pre-emptively reintroduces the governance friction `x-` exists to avoid. | Nothing today |
| G2 | Proposal | **No per-property size bound on an extension value.** Deliberate: tarball + manifest size caps in `SECURITY/threat-model-node-packs.md` already bound it transitively, and a second cap is a second place to drift. | Security Architect | Revisit if a registry reports manifest bloat traceable to extensions. Would land as a bound in the existing size-cap row, not a new one. | Nothing today |
| G3 | Compatibility | **Round-trip fidelity is permitted but not required.** A host MAY retain raw extension bytes across install → re-export; nothing requires it. A pack could therefore lose its extensions by transiting a host. | Compatibility Architect | Needs a host that actually round-trips packs to validate the requirement against. None does today, so specifying it would be fabricating a contract from zero implementations. | A future `Accepted` gate on pack round-tripping |
| G4 | Out of scope | **`prompt-template.schema.json` and `agent-manifest.schema.json` are untreated.** Both are closed (`additionalProperties: false`, no hatch), so the same `host-extensions.md` contradiction technically persists there. Excluded here because they are separate contracts with their own compatibility surfaces, not pack-manifest structure. | RFC 0028 / RFC 0002 owners | Their owners decide. Listed by name in the conformance scenario's `OUT_OF_SCOPE` map so the exclusion is a stated decision that a future reader can find, not a hole. | Nothing in 0138 |
| G5 | Motivation | **The persisted-`artifactTypeId` migration constraint is answered but not solved.** The requesting host cannot migrate `doc.one-pager` / `brand.kit` to reverse-DNS form without editing durable `RunArtifactRecord` rows. RFC 0138 §Implementation notes states the position (host-side concern, three legitimate strategies, no protocol surface owed) but the corpus still lacks prose saying legacy ids were never wire-conformant. | RFC 0071 owners | Its own RFC. Recorded here so the constraint is answered rather than silently inherited by 0138. | The requesting host's full pack migration — **not** its extension migration, which 0138 unblocks today |
| G6 | Conformance | **No leg asserts a HOST accepts a canonically-shaped extended manifest** — only that the schema does. The suite validates shape server-free; nothing exercises a host's loader accepting an extended pack. This is the same class of gap that let a reference host's `artifactTypePackLoader` accept only inline `schema` and silently reject `schemaRef`. | Conformance Architect | Needs a host-sample seam (`POST /v1/host/sample/packs/install`) behind `behaviorGate`. Genuinely out of scope for 0138 — the gap predates it and spans every declarative kind. | An `Accepted` gate that claims host-side extension handling is verified |
| G7 | Security | **Nothing detects a host that violates MUST-ignore.** The invariant is stated and the prose is asserted, but a host that renders an extension value fails no test — the violation is behavioral and the suite's coverage here is server-free. | Security Architect | Same seam as G6. Until then the invariant is enforced against the *corpus*, not against *hosts*, and `pack-manifest-extension-opaque`'s note says so rather than overclaiming. | Nothing today; bounds what the invariant may be said to prove |
