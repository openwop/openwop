# RFC 0106 — Gap Register

Open questions, deferred decisions, and missing inputs beyond the in-template Unresolved questions. Each gap has an owner and a resolution path. A gap with no path is promoted to a Risk (see `.risks.md`).

**Deep-dive update (2026-06-23):** G1, G4, G5 are **RESOLVED** via a web + codebase research pass (4 agents: SDK streaming-type inspection; streaming-ASR API survey; live-stream-handle cross-protocol survey; live-audio threat-model). Resolutions folded into the RFC §B/§B.1/§F.

**`Draft → Active` update (2026-06-23):** the 7-day additive comment window was waived per GOVERNANCE.md lazy consensus and the **gating G10 is RESOLVED** (author confirmed the four Draft resolutions). Because `Active` locks the wire shape, the `Active`-gated opens are all resolved in-RFC at the flip: **G2, G3, G8, G9 RESOLVED** (see RFC §"Resolved questions"), **G6** filed as a named post-`Active` follow-on tracking item (not in 0106). The only gap that survives to `Active → Accepted` is **G7** (a named reference host committing to advertise `realtimeVoice`) — that is the Accepted gate, now in active coordination with openwop-app.
