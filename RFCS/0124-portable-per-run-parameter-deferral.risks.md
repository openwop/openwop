# RFC 0124 — Risk Register

Companion to `0124-portable-per-run-parameter-deferral.md`. Likelihood × Impact scored H/M/L. Critical/High risks carry a named mitigation owner.

| ID | Risk | Likelihood | Impact | Score | Mitigation | Owner | Status |
| --- | --- | --- | --- | --- | --- | --- | --- |
| R1 | **Run-time parameter injected into a prompt is untrusted content.** A per-run `configurable` override of a materialized variable feeds directly into `PromptTemplate.text` — a prompt-injection vector that the expansion-time (author-trusted) model did not have. | H | H | **High** | **Tightened to a MUST (step 4), unconditional.** Every deferred-variable prompt binding MUST compose with `bindingTrust:"untrusted"` → `contentTrust:"untrusted"` + `<UNTRUSTED>` fencing; hosts MUST NOT branch on default-vs-override provenance (footgun). Conformance asserts `contentTrust:"untrusted"` on the composed payload. **Mitigation already exists in the reference implementer** (openwop-app `promptCompose.ts` / `promptInjectionGuard.wrapForLLMPrompt`, conformance-exposed) — this reuses the existing fence, not new surface. | Security Architect | Mitigated (MUST + existing fence) |
| R2 | **`sensitive` parameter leaks — at-rest (persisted plaintext) AND observability (`prompt.composed`).** The graver vector (surfaced by the openwop-app security review): under expansion-time substitution a `sensitive` param is frozen into persisted `config` in plaintext = secret-at-rest leak in the stored WorkflowDefinition. Plus the observability leak if not redacted. | M | H | **High** | **Mitigated (§Security MUSTs):** `x-openwop-sensitive:true` ⇒ (a) deferred-only / fail-closed — a recognizing host MUST NOT expansion-time-freeze it; MUST defer or refuse to expand (no secret at rest); (b) MUST redact to `[REDACTED:<id>]` in `prompt.composed`/debug per SR-1. Residual: pre-RFC hosts ignore the key (documented; future capability-gate). Conformance: at-rest (no plaintext sensitive in persisted def) + fail-closed + redaction legs. | Security Architect | Mitigated (MUSTs) |
| R3 | **Portability regression via the escape hatch.** A host implements deferred mode but leaves an embedded non-prompt `{{params.*}}` token unresolved (skips the "resolve at expansion time" fallback), silently reintroducing the exact non-portable state this RFC exists to prevent. | M | H | **High** | Step 3 makes persisting any `{{params.*}}` token non-conformant under ALL modes; server-free scenario asserts zero residual tokens after deferred expansion. | Conformance Architect | Open |
| R4 | **Fork/replay non-determinism if overrides bypass the event log.** A host applies per-run overrides through a machine-local path instead of `configurable`, so a `:fork` replays with different bound values. | L | H | **Med** | Overrides MUST travel as `configurable` (event-logged); `replay.md` §Determinism already requires `RunSnapshot.variables` byte-equivalence. Host-leg conformance asserts fork replays the same value. | Conformance Architect | Open |
| R5 | **INTEROP-MATRIX drift.** Third-party/reference hosts adopt `deferredParameters` but stay on an older conformance suite → matrix advertises a capability with no gated evidence. | M | M | **Med** | Gate all host legs on `workflowChainPacks.deferredParameters.supported`; honest-off advertisement until a witness passes; matrix column added in the same PR as the scenario. | Conformance Architect | Open |
| R6 | **Two hosts diverge on variable-naming, breaking cross-host override keys.** Without a pinned naming/alias scheme, host A's `configurable` key won't match host B's materialized variable, so a portable workflow's overrides silently no-op on the other host. | M | M | **Med** | **Mitigated (review):** normative override key is the bare param name; hosts MUST auto-generate the `configurableSchema` bare→prefixed mapping (§"Override key + variable naming"). Conformance asserts the bare-param override key resolves cross-host. | Spec Architect | Mitigated (pinned) |
