# RFC 0129 — Risk register

Companion to `0129-data-residency-region-advertisement-and-honor-or-reject.md`.
Identified risks with likelihood/impact and mitigation. Working document; does not gate
the flip except where a risk is unmitigated.

| ID | Risk | Likelihood | Impact | Score | Mitigation | Owner | Status |
| --- | --- | --- | --- | --- | --- | --- | --- |
| R1 | **Compliance-theater reading** — an operator (or auditor) reads `dataResidency.supported: true` as a *guarantee that data physically stays in region*, when the wire only enforces admission control (§3). | High | High | H | RFC §4 states explicitly the wire enforces admission, NOT physical location; the capability description in `capabilities.md` MUST say "honors-or-rejects a region constraint", never "guarantees data residency". Same mitigation as 0128 R1 (say "propagates labels", never "enforces purposes"). | Spec Architect | Open (mitigated) |
| R2 | **Silent-accept regression** — a host advertises `dataResidency` but a code path accepts an unadvertised region and runs it anyway (the exact harm §3 forbids), passing an inattentive review. | Med | High | H | Conformance scenario 2 (`unadvertised-region reject`) is non-vacuous under `REQUIRE_BEHAVIOR`; the fail-closed admission check lives at the run-creation route boundary, route-tested. | Conformance Architect | Open (mitigated) |
| R3 | **Region-code fragmentation** — opaque operator strings (`eu` vs `eu-west-1` vs `EU`) drift, so a client's requested region never matches a host's advertised set and every pinned run is rejected. | Med | Med | M | Accepted as a named residual: matching is exact-string and case-sensitive; a shared region registry is additive later (RFC §Resolved Q1) if an interop gap appears. Clients read the host's advertised `regions[]` and echo a value from it. | Spec Architect | Open (accepted residual) |
| R4 | **Unfalsifiable-MUST creep** — a later amendment adds a normative claim about physical data location or cross-region transfer that a conformance run cannot refute, re-introducing the dishonesty this RFC was scoped to avoid. | Low | High | M | Governance guard: any amendment touching §4 must pass the falsifiability check (does a conformance run refute it over the wire?) before it becomes a MUST. Recorded as the RFC's defining constraint. | Spec Architect | Open (mitigated) |
| R5 | **Author-is-witness** — the reference host (openwop-app) authors the RFC and provides the tier-1 witness. | Low | Med | L | Steward independently curl-verifies the admission behavior (accept advertised / reject unadvertised) against the live host before the flip, per the 0127/0128 arc. Single-witness graduation under the bootstrap-steward waiver with the tier-2 gap named (G4). | Steward | Open (mitigated on verify) |
