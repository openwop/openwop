# RFC 0120 — Risk Register

Scored Likelihood × Impact (H/M/L). Critical/High → named mitigation owner + target.

| ID | Risk | Likelihood | Impact | Score | Mitigation | Owner | Status |
|---|---|---|---|---|---|---|---|
| R1 | A typo'd or malicious `apiHosts` entry aims a resolved credential at a wrong registrable domain (confused-deputy widening — the field's whole purpose is to widen where a token may go). | L | H | **Med** | (a) The host-shape MUST (§B.7) forbids URL/wildcard/IP/single-label, keeping each entry a tight registrable host; (b) eTLD+1 suffix match (never substring) blocks `evil-facebook.com` from matching `facebook.com`; (c) packs are **operator-installed + signed** (node-packs threat model) — the trust boundary is the operator, same as the OAuth client secret; (d) new SECURITY invariant `connection-pack-api-host-shape` + public test. The credential is still only sent host-side (RFC 0046/0047 unchanged) — `apiHosts` constrains a destination, it does not expose the credential. | Security Architect | Open — target: Active |
| R2 | Pack authors omit `apiHosts` and the provider silently fails closed at egress (the SHOULD, not MUST, of §B.9), surfacing as a confusing "nothing happened". | M | M | Med | §B.9 requires hosts to surface an honest "provider unreachable for egress" (not a silent no-op); the conformance fail-closed-default scenario codifies it; G1 decides whether to harden to MUST. | Spec Architect | Open |
| R3 | INTEROP drift: a host advertises `connections.packsSupported` but bundles an old manifest schema, so a pack with `apiHosts` is rejected (`additionalProperties:false`) on that host while validating on updated hosts. | M | M | Med | Frame as a **suite-version** requirement (Compatibility §); gate the conformance scenarios on the suite version; INTEROP-MATRIX note that `apiHosts` is a suite-N field. Additive — old hosts simply keep failing closed (no worse than today). | Compatibility Architect | Open |
| R4 | Over-broad eTLD+1 entry (`googleapis.com`) authorizes the token to *all* Google API subdomains, broader than the single intended API host. | L | M | Low | Document the eTLD+1 trade-off (G3); a pack MAY enumerate exact subdomains if it wants tighter pinning; the credential is provider-scoped anyway (a Google Ads token is only valid for Google APIs). Revisit exact-host matching if a real over-scope case appears. | Spec Architect | Open |
| R5 | Scope creep: reviewers push to also let `apiHosts` carry ports, paths, or methods (turning the allow-list into a mini-policy language). | L | M | Low | Keep the field a **bare-host allow-list** only (§B.7); any richer egress policy belongs in RFC 0079's provenance/egress-policy layer, not the connection-pack manifest. State this boundary in the RFC. | Spec Architect | Open |
