# RFC 0137 — Gap Register

Companion to [`0137-form-content-packs.md`](./0137-form-content-packs.md). Open questions, deferred decisions, and missing inputs beyond the in-template §Unresolved questions. Each gap carries an owner and a resolution path; a gap with no path is promoted to the [risk register](./0137-form-content-packs.risks.md).

| ID  | Section              | Question / Missing Input                                                                                                                                                                                                                                                                                       | Owner                   | Resolution Path                                                                                                                                                                        | Blocks                   |

| G1  | Proposal / §UQ1      | Conditional field visibility (`show X iff Y == Z`) is unspecified. The corpus already has an edge-condition operator set (`workflow-definition.schema.json` §EdgeCondition, extended by RFC 0134); reusing it beats minting a second expression language, but it is not obviously right for field-level predicates. | Spec Architect          | Defer to a follow-up RFC once an adopter needs it. Evaluate `EdgeCondition` reuse FIRST — an independent second vocabulary is the failure mode this RFC exists to prevent (see §Alt 3). | Nothing (v1 ships without) |
| G2  | Proposal / §UQ2      | Per-field validation beyond `required` + `format` — no `minLength` / `min` / `max` / `pattern`. `pattern` is the hard one: a regex authored by an untrusted pack author is a ReDoS surface.                                                                                                                        | Security Architect      | If admitted later, it MUST inherit the RFC 0071 bounded-compilation treatment (`artifact-schema-compile-bounded`). | G11 | Amendment A1 | **Cross-kind, not form-content-specific.** Identifier uniqueness (`nodes[].typeId`, `artifactTypes[].artifactTypeId`, `cards[].cardTypeId`, `chains[].chainId`, `templates[].templateId`, `fields[].id`) is stated in prose in every pack manifest and enforced by no schema — JSON Schema cannot express uniqueness-by-property. `registry-operations.md` §"Validation flow" names no duplicate-id check for ANY kind. | Spec Architect | RFC 0137 adds the normative section + registry/host refusal for `form-content`. | G12 | Acceptance criteria | **The `Active → Accepted` gate was unsatisfiable as originally written** — every leg shipped with the RFC was server-free, so `OPENWOP_REQUIRE_BEHAVIOR=true` had no host-touching leg to make non-vacuous. Found by the reference host when it went to run the gate. | Conformance Architect | CLOSED — `form-content-instantiation.test.ts` added 2026-08-05, non-vacuity verified against a stub host (refuse / lock / route each red exactly one leg). | G13 | Security (cross-kind) | **Tool-result trust is unspecified corpus-wide.** The host reports (`FRMD-F1-1`) that sibling agent tools can launder taint: its `crm` / `service-desk` / `priority-matrix` tools return records that the forms submission sinks WROTE — the same attacker-controlled bytes under a different tool id, unfenced. RFC 0137 cannot reach them without over-claiming scope, and the corpus has per-surface trust rules (`chat-card-input-trust-boundary`, `node-pack-output-untrusted`, `form-content-pack-string-trust-boundary`) but no general "a tool result is untrusted content" rule. | Security Architect | Out of scope for RFC 0137 — a general tool-result trust boundary is its own RFC, spanning `tool-catalog.md` / `host-capabilities.md` §tools / the prompt-injection threat model. Logged here so the gap is recorded rather than lost; the host tracks its instance in ADR 0516. | Nothing in RFC 0137 |
| G14 | Conformance (cross-cutting) | **Three capability-gated behavioral scenarios still soft-skip via a bare `return` instead of `behaviorGate`**, so `OPENWOP_REQUIRE_BEHAVIOR=true` cannot fail on an unadvertised/mis-spelled capability: `artifact-type-pack-install.test.ts`, `artifact-type-store-without-render.test.ts` (both `host.artifactTypes`) and `chat-card-pack-execution.test.ts` (`host.chat.cardPacks`). Found because the reference host reported its `discovery.ts` carries ZERO dotted `host.*` keys — every family is nested and un-prefixed — so those RFC 0071 legs have likely never executed against it despite the behavior being implemented. | Conformance Architect | RFC 0137's own leg is fixed (`form-content-instantiation.test.ts` now uses `behaviorGate`; verified loud in strict mode). The other three belong to RFC 0071 surface and are a separate sweep — not changed unilaterally here because flipping them to loud will newly FAIL any host whose advertisement was silently invisible, which is a grading change those RFCs' owners should make deliberately. | Nothing in RFC 0137 |
