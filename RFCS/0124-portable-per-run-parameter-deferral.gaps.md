# RFC 0124 — Gap Register

Companion to `0124-portable-per-run-parameter-deferral.md`. Open questions, deferred decisions, and missing inputs beyond the in-RFC Unresolved questions. Each gap has an owner and a resolution path; a gap with no path is promoted to a Risk.

| ID | Section | Question / Missing Input | Owner | Resolution Path | Blocks |
| --- | --- | --- | --- | --- | --- |
| G1 | Proposal §Deferred expansion | Materialized variable naming (`${chainIdSlug}_${expansionId}_${p}`) is collision-safe but ugly for author-facing `configurable` override keys. Need a friendly-alias mechanism (likely a generated `configurableSchema` mapping bare param → prefixed variable). | Spec Architect | Decide in comment window; pin before `Active` (Unresolved Q1). | `Active` status; conformance host-leg override key |
| G2 | Security | No deterministic way to know a chain parameter carries secret-class material → cannot make `sensitive: true` a `MUST`. Need either an OPTIONAL manifest hint (`parameters.properties.<p>.x-openwop-sensitive`) or a documented `SHOULD` + host judgment. | Security Architect | Decide hint-vs-SHOULD in comment window (Unresolved Q2); if hint, add to `workflow-chain-pack-manifest.schema.json`. | Tightening redaction invariant to `MUST`; `Active` |
| G3 | Proposal §Rewrite targets | Detecting "prompt-bearing config" reliably: a chain may put a prompt in `config.systemPrompt` (inline body) rather than `config.systemPromptRef` (PromptTemplate). Inline bodies have no `{{varName}}` interpolation surface unless the host lifts them into a PromptTemplate at expansion. Need to specify whether deferred mode MUST lift inline prompt bodies into templates. | Spec Architect | Spec prose decision at `Active`; likely "host MUST lift the inline body into a host-resident PromptTemplate to defer it, else resolve at expansion time." | Rewrite-target completeness |
| G4 | Conformance | `configurableSchema` interaction: materialized variables should be override-validated. Unclear if deferred expansion auto-extends the parent's `configurableSchema` or leaves it to the author. | Conformance Architect | Resolve with G1 (Unresolved Q1/Q4). | Host-leg override-validation assertion |
| G5 | Compatibility | `capabilities.prompts.variableSources` must include `variable` for the prompt-rewrite path. If a host advertises `deferredParameters.supported` but not `prompts` `variable` source, the fallback ("resolve at expansion time") is specified but untested. | Conformance Architect | Add a negative-capability conformance leg. | `Accepted` scenario completeness |
| G6 | Reference host | Second witness for `Accepted` not yet identified (openwop-app is witness #1). In-memory reference host has no prompt-template compose path today — may not be the natural second witness. | Compatibility Architect | Identify a tier-2 sibling (MyndHyve `workflow-runtime`?) or extend the in-memory host. | `Accepted` dual-witness |
