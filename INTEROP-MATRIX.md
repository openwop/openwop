### Conformance pass rates

Measured against `@openwop/openwop-conformance@1.22.0` — all five hosts re-measured 2026-06-11 (in-memory/python/postgres in default mode, Postgres via the pglite entry point, SQLite under strict mode with honest profile/fixture opt-outs, workflow-engine in-process at the production-deployed commit `3537d3c8` with `--no-file-parallelism` for determinism). Suite total is 1963 (+9 tests from the 5 RFC 0093/0094 scenario files). **Measurement-basis note:** this run loads the full 82-fixture catalog into the example hosts; the 2026-06-09/1.21.0 readings were taken with degraded fixture loading (the hosts' upward fixture probe finds the catalog only when nested inside the spec repo), so passed/skipped shifts vs that baseline reflect broader coverage, not host changes. **Honest failure accounting:** the in-memory host's 45 failures remain advertised-fixture surfaces the minimal host doesn't implement (unchanged set); the workflow-engine's 12 failures are its known pre-existing set (agent-pack/reducer/replay/stream-reconnect family — 0 new at 1.22.0). **New real finding:** the RFC 0093 §A3 `webhook-tenant-isolation.test.ts` scenario fails on SQLite, Postgres, and Python (2 deterministic failures each) — these hosts advertise `webhooks.supported: true` but lack a registration-time tenant-membership gate, so this is a genuine gap on an advertised surface, not an honest non-claim; the fix is tracked in `openwop-examples`. SQLite's strict gate additionally needs its opt-out list extended for the 1.22.0 profiles (`openwop-grpc-transport`, `openwop-i18n`) — with that extension its remaining failures are the 2 webhook ones. ## Reading Rows

- **Compatibility profile claim** is derived from `/.well-known/openwop` according to `spec/v1/profiles.md`.
- **Scale claim** follows `spec/v1/scale-profiles.md`.
- **Production profile claim** follows `spec/v1/production-profile.md` and is recorded separately because durability, retention, backpressure, and observability are operational evidence, not discovery-payload predicates.
- **Conformance evidence** should name the suite version, command used, target URL class, and pass/fail/skip counts. Do not include private deployment identifiers, secrets, or internal result paths.

## Add A Host

1. Implement the openwop v1 wire contract.
2. Run `@openwop/openwop-conformance` against the host.
3. Publish a result file or Markdown summary in a public repository.
4. Add a row above with compatibility, scale, production-profile, and evidence claims.
